# 호스트 동기화 서버: 기기별 쓰기 권한 (v1.41)

PC 가 호스트일 때 페어링한 휴대폰이 호스트 폴더(`docs/HOST-STORE.md`)를 **읽고**, PC 에서 허용한 기기만 **쓴다**. 폰 쪽 Provider·화면은 v1.42 이다 — 이번 버전은 **PC 쪽 서버·권한·화면**이다.
정책 출처: `docs/SYNC-HOST.md` §3(권한 모델)·§5(조건부 쓰기)·§3.1(실행 파일).

## 구성
- `electron/hostServer.cjs`: HTTPS 서버. **별도 서버(기본 포트 47412)·별도 연결 코드·별도 기기 토큰**이다. 인증서는 공유 폴더 서버(`fileShare`)와 **같은 PC 인증서**라 폰이 고정하는 지문이 하나다(`fileShare.register()` 가 `getTls` 를 돌려준다).
- `electron/hostIpc.cjs`: `hostsrv:get/set/newCode/revoke/setPerms` — **이 PC 의 화면에서만** 켜고 권한을 바꾼다. 서버를 켜 두었으면 앱이 준비된 뒤 다시 연다. 호스트 폴더를 해제하면 서버도 끈다.
- 화면: 설정 > 노트와 동기화 > (호스트 폴더 연결됨) 고급 > "휴대폰과 맞추기"(`HostConnect.tsx`): 켜기, QR·코드·연결 문자열, 기기 목록(마지막 사용·쓴 횟수), 기기별 "읽기만 / 쓰기 허용됨" 스위치(켤 때 확인 창), "삭제 불가"(비활성), 해제.
- 연결 문자열 `nsh1:<ip,ip>:<port>:<6자리 코드>:<인증서 지문 64자>` (공유 폴더는 `nsf1`).

## 권한
| 권한 | 기본 | 누가 바꾸나 | 비고 |
| --- | --- | --- | --- |
| 목록·읽기 | 허용(페어링된 기기) | — | `/list` `/get` |
| 쓰기 | **꺼짐** | PC 화면에서 기기별로 | `/put`. 켠 뒤에는 매번 확인하지 않는다. 끄면 **다음 요청부터** 막힌다 |
| 삭제 | **꺼짐**(기기마다 기본) — PC 앱은 켤 수 있게 해 둠(`allowDelete`, v1.43.6) | PC 화면에서 기기별로(쓰기가 먼저 켜져 있어야 하고, 켤 때 확인 창) | `/delete`. 쓰기를 끄면 삭제도 함께 꺼진다. 지운 파일은 휴지통(90일)+삭제 기록으로 간다. **분당 30회** 한도(429). `allowDelete` 가 꺼진 서버(시험 기본)에서는 켤 수 없다 |
| 권한 올리기 | 불가 | — | 기기가 자신의 권한을 바꾸는 요청이 서버에 없다(시험: 404, 권한 그대로) |
- 기기 해제는 즉시 적용되고 호스트 manifest 의 기기 목록에서도 빠진다(삭제 기록 정리에서 더 기다리지 않는다).
- 기기는 5대까지, 코드는 6자리·5분·한 번만·5번 틀리면 1분 잠금, 토큰 실패 20번이면 잠시 차단.

## 폰에서 연결 해제 (`POST /unpair`)
- 짝 맺은 기기가 토큰으로 **자기 자신만** 호스트의 기기 목록에서 지운다(기기 쓰기 기록·삭제 기록 정리 포함, 해제와 같은 함수). 폰의 `연결 해제`가 PC 의 "연결된 휴대폰"에도 반영되게 한다. 권한이 없는 기기를 올리는 경로는 여전히 없다.

## 쓰기 (`POST /put { path, baseRev, b64 }`)
1. 쓰기 권한 확인 — **본문을 읽기 전에** 거절한다(큰 파일을 받지 않는다) → 403 `noWrite`.
2. 25MB 초과 413 · **실행 파일 403 `executable`**(차단 확장자 `.exe .dll .msi .bat .cmd .com .scr .ps1 .vbs .lnk .jar .apk …` + 파일 머리 PE `MZ`·ELF·Mach-O — 이름을 바꿔도 막는다. 보조 방어이고, 진짜 방어선은 호스트가 어떤 파일도 열거나 실행하지 않는 것) · 분당 120회 초과 429 · PC 여유 공간 부족(파일 + 200MB) 507.
3. `hostStore.put` — **조건부**(baseRev 가 현재 rev 와 같을 때만, 다르면 아무것도 쓰지 않고 409 + 현재 rev·`deleted`)·**원자적**(tmp → journal → rename → manifest)·경로 우회(`..`·숨김·`.nosidian`·예약 이름·절대 경로)·링크(정션·심볼릭) 거절. 누가 썼는지 manifest 에 `device:<id 앞 8자>` 로 남는다.
- PC 에서 먼저 탐색기로 고쳤으면 폰의 옛 rev 쓰기는 409 — 덮어쓰지 못한다. 지워진 경로에 폰의 오래된 사본이 새로 만들 수 없다(삭제 기록의 rev 를 알아야 한다: `/list` 의 `tombs`).
- PC 사용자가 직접 폴더에 넣은 실행 파일은 막지 않는다(폰이 읽을 수는 있다). 호스트는 파일을 열거나 실행하지 않는다.
- `/ack { seq }`: 폰이 여기까지 반영했다는 확인 → 삭제 기록 정리 조건(`docs/SYNC-HOST.md` §6.1).

## 한계·미구현
- 폰 쪽 클라이언트(Provider·화면·QR 스캔·권한 거절 안내)는 **v1.42**. 이번 시험의 "폰"은 Node 의 HTTPS 클라이언트이고, 실제 폰 기기로는 아직 쓰기를 해 보지 않았다.
- **삭제 전파(v1.43.6)**: 삭제를 허용한 기기에서 지운 파일은 호스트에서도 휴지통으로 간다(`docs/HOST-PHONE.md` "삭제 전파·휴지통·자동 동기화"). 허용하지 않은 기기의 삭제는 전파되지 않고 폰에 안내한다(v1.42).
- 속도 제한은 메모리에만 둔다(앱을 다시 켜면 초기화). 호스트 폴더 총용량 상한은 없다(여유 공간 검사만).
- 폰의 토큰은 Android Keystore(v1.39)에 둔다. PC 쪽 기기 토큰은 해시로만 보관한다.

## 실제 PC 앱에서 확인한 것 (Electron, 시험 폰 = Node HTTPS 클라이언트)
- 서버 켜기(QR·코드·연결 문자열) → **지문을 확인하며** 짝 맺기 → 읽기 OK, **기본 쓰기 403(noWrite)**.
- PC 화면: 기기가 "읽기만 / 삭제 불가"로 보임 → 쓰기 허용 클릭 시 **확인 창**(취소하면 그대로, 허용하면 "쓰기 허용됨") → 새 노트 200, 맞는 rev 로 갱신 200, 옛 rev 409, **PC 에서 탐색기로 먼저 고친 뒤 폰의 옛 rev 쓰기 409(PC 내용 유지)**.
- 실행 파일: `.exe` · `.dll` · 이름을 바꾼 PE 머리 파일 모두 403, 폴더에 남지 않음. 일반 `.py` 는 저장되고 manifest 에 `device:<id>` 로 기록.
- 쓰기 회수 → 다음 요청부터 403(읽기는 계속 됨) → 기기 해제 → 401 → 서버 끄기 → 연결 거부.
- PC 앱 재시작 후: 서버 자동 재개, 기기·권한·토큰 유지, 같은 인증서 지문, rev epoch 동일.
- **실제 폰 기기로는 아직 쓰기를 해 보지 않았다**(폰 쪽 Provider·화면은 v1.42).
