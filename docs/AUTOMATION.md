# AI 자동 문서 관리 — 설계안 (v1.28~v1.30, 미구현)

원칙: **규칙 검사는 항상, AI 분석은 조건부, 문서 변경은 승인 기반.** 기본값은 꺼짐(알림만).

## 1. 수준
| 모드 | 동작 | 단계 |
|---|---|---|
| 꺼짐 | 아무것도 안 함(현재) | 기본 |
| 알림만 | 새 문제가 생기면 알림. AI 안 부름 | v1.28 |
| AI 자동 분석 | 새 문제를 읽기 전용으로 분석해 정리 계획을 확인할 문제 목록에 보관. 문서 수정 없음 | v1.29 |
| 제한적 자동 수정 | **범위 밖.** 실제 사용 데이터로 안정성을 본 뒤 별도 결정 | — |

## 2. GPT 검토안에서 바꾼 점 (코드 현실 반영)
1. **자동 분석은 AI 패널 대화를 쓰지 않는다.** 패널의 `running`·대화는 사용자 것이다. 자동 분석은 별도 "확인할 문제 목록"에 결과를 쌓고, [정리 계획 검토]를 누르면 그 계획을 패널 대화에 `fix:'plan'` 메시지로 넣어 기존 [이 계획대로 변경 제안 만들기]·묶음 승인을 그대로 쓴다.
2. **사용자 요청이 항상 우선.** 사용자가 패널로 묻는 중이면 자동 분석은 대기한다. 자동 분석 중 사용자가 물으면 자동 분석을 취소하고 대기열로 되돌린다(엔진 한 번에 한 작업).
3. **켜는 순간의 기존 문제는 "기준선"으로 처리.** 안 그러면 켜자마자 기존 점검 항목 전체가 분석되어 한도·비용이 소진된다. 기존 문제는 "기존 N건"으로만 표시하고, 사용자가 직접 [AI로 고치기]를 누른다.
4. **다기기 조율 문제는 없다.** AI 엔진은 PC(Electron)에만 있으므로 자동 실행도 PC 한 곳뿐이다. 폰은 알림 표시만 가능(v1.28 이후 별도 검토).
5. **Claude 엔진 자동 사용은 별도 동의.** 자동 분석은 사용자가 누르지 않아도 노트 내용이 Anthropic 으로 나간다. 설정에서 "Claude 로 자동 분석 허용"을 따로 켜야 하고(기본 꺼짐), Ollama 는 로컬이라 이 동의가 필요 없다. 구독 사용량을 쓴다는 점도 함께 표시한다.
6. **트리거는 지금 있는 점검 종류로 한정.** "공식 문서 간 내용 충돌", "프로젝트 완료", "보조 문서 누적"은 점검 규칙이 아직 없다. v1.28 트리거는 `중복 후보`·`역할 충돌`·`규칙 위반 중 AI 판단이 필요한 것`만. 누락 제목·status·끊어진 링크 같은 기계적 문제는 AI를 부르지 않는다(알림만). 새 점검 종류는 v1.30 이후.
7. **잘린(truncated) 노트가 걸린 문제는 자동 분석 제외**(수정 금지 정책과 같은 이유). 알림에 "내용이 길어 자동 분석 안 함"으로 표시.

## 3. 파이프라인
```
vault 변경(저장·이동·삭제·동기화) → ①변경 모으기(30초 debounce, 앱이 켜져 있을 때만)
 → ②점검 실행(기존 doclint, AI 없음) → ③이전 점검 결과와 비교 → "새로 생긴 문제" 추출
 → ④분석 후보 판정(§4) → ⑤대기열 등록 → ⑥실행 정책 확인(§5) → ⑦(v1.29) 읽기 전용 AI 분석
 → ⑧확인할 문제 목록 카드 → 사용자 검토 → 변경 제안 → 최종 승인(기존)
```
- 앱을 다시 열면 마지막 기준선과 비교해 누적 변경을 한 번 점검한다.
- 이 파이프라인은 AI 를 켜지 않아도 ①~⑤가 "알림"으로 동작한다.

## 4. 새 문제 판정 · 분석 키
- 문제 키 = `종류 + 관련 노트 경로(정렬) + 관련 노트 내용 해시 + 규칙 파일 해시`. 기준선에 이미 있는 키는 새 문제가 아니다.
- 다른 노트를 고쳤다고 같은 문제가 다시 새 문제가 되지 않는다(관련 노트 해시만 키에 들어가므로).
- 관련 노트가 바뀌어 키가 달라지면 "문제가 바뀜"으로 보고 새로 등록하되, **AI 변경 제안을 사용자가 승인해 생긴 변경**은 해당 경로를 일정 시간(기본 24시간) 자동 분석에서 제외한다(AI → 변경 → 자동 재분석 반복 방지). 사용자가 직접 [AI로 고치기]를 누르는 것은 언제나 가능.
- 분석 결과 캐시: 같은 키는 재분석하지 않는다. 키의 노트가 바뀌면 확인할 문제 목록 카드는 "오래됨"으로 표시하고 계획 실행 버튼을 막는다(기존 base hash 재검증과 일치).

## 5. 실행 정책 · 제한
- 한 번에 한 작업. 하루 최대 N회(1/3/5/10, 기본 3). 문서 변경 후 대기(30초/2분/5분, 기본 30초).
- 실패: 같은 키는 1시간 뒤 1회만 재시도. 연속 3회 실패하면 자동화를 일시정지하고 알림.
- 보류 조건: 엔진 연결 안 됨(Ollama 서버 없음, Claude CLI 로그인 안 됨), 설정한 경우 배터리 사용 중, 사용자가 AI 와 대화 중.
- 자동 분석은 **읽기 전용 고정**: 내부 MCP `readOnly`·모드 'ask'. `propose_change`가 불가능하고 `forceApproval`도 쓰지 않는다. 테스트로 "자동 분석 경로에서 제안이 만들어지지 않는다"를 고정한다.
- 보호 경로(`_workspace/`)는 분석 대상 노트로 넘기지 않는다(기존 정책 유지).
- 프로젝트별 끄기: 문서 규칙이 꺼진 프로젝트는 자동 관리도 안 한다. 프로젝트마다 "자동 관리 제외" 가능.

## 6. 저장
| 데이터 | 위치 |
|---|---|
| 프로젝트 문서 규칙 | `_workspace/문서규칙.md` (자동화 설정은 넣지 않는다 — 기기별 비용·동의 문제) |
| 자동화 설정(모드·트리거·한도·동의) | 기기 로컬 설정 |
| 기준선·분석 키·대기열·이력·확인할 문제 목록 | 기기 로컬, vault 별. 항목이 늘 수 있어 IndexedDB 의 별도 저장소 (제안 목록은 지금 localStorage 라 같이 옮길지 v1.28 에서 결정) |
| 감지된 문제 | 저장하지 않음(Markdown 에서 매번 계산) |
| 최종 문서 | vault Markdown |
- 확인할 문제 목록·이력은 기본 30일 또는 200건까지만 보관.

## 7. 설정 UI (설정 > AI 자동 관리, PC 전용)
자동 관리 모드(꺼짐/알림만/AI 자동 분석) · 트리거 체크(새 중복 후보, 역할 충돌, 규칙 위반 중 판단 필요) · 사용 엔진(패널 선택 / Ollama 우선) · Claude 자동 사용 허용 · 하루 최대 · 변경 후 대기 · 배터리 시 보류 · 지금 일시정지.
선택한 정책의 예상 동작을 한 줄로 보여 준다("문제 발견 후 30초 모아 하루 최대 3회 분석, 문서는 자동 수정 안 함").
**v1.28 에는 "시험 실행(dry-run)" 보기**를 둔다: "이 설정이었다면 최근 변경에서 어떤 문제를 AI 에 보냈을지"를 AI 없이 보여 준다 → 트리거 조건을 실제 vault 로 검증.

## 11. v1.28 구현 현황 (트리거·대기열, AI 호출 없음)
구현: `lib/autoTriggers.ts`(순수), `lib/autoStore.ts`(vault 별 IndexedDB `nosidian-auto-<vault>` + 기기 설정 localStorage), `lib/automation.ts`(스케줄러·상태), `components/AutoSettings.tsx`(설정 > AI 자동 문서 관리), `lib/aiChangeHook.ts`.
- 화면 이름: "확인할 문제"(= 새 문제 목록 = 앞으로 AI 분석 대기열). 설계 초안의 "받은 편지함"은 어색해서 바꿨다.
- **기준선**: 처음 점검(자동 관리가 꺼져 있어도), 자동 관리를 켤 때, 프로젝트에 규칙을 새로 적용할 때 지금 있는 문제를 기준선으로 기록한다. 기준선과 이력은 vault 별로 저장돼 재시작·vault 전환 뒤에도 유지된다.
- **새 문제 판정**은 문제의 정체성(종류+프로젝트+관련 노트+값)으로 한다. 같은 문제에서 노트를 더 고쳐도 새 문제가 아니고, 사라졌다 다시 생기면 새 문제다. 서로 겹치는 중복 후보 쌍(A↔B, B↔C, A↔C)은 한 묶음(1건)으로 합친다.
- **문서 버전**: 대기 항목은 등록 시점의 노트 해시를, AI 분석 결과(v1.29)는 분석 시점의 해시를 가진다. 원본이 바뀌면 "문서가 변경되어 재검토가 필요합니다"를 보이고 계획 실행을 막는다(`isStale`·`canExecutePlan`).
- **중단 vs 실패**(v1.29 가 쓸 기록 함수는 지금 구현·시험됨): 사용자의 중단은 실패 횟수·하루 한도를 소모하지 않고 대기열로 돌아가며, 이미 쓴 사용량(시간·비용)은 기록한다. 실패는 한도·실패 횟수를 소모, 1시간 뒤 1회 재시도, 연속 3회 실패 시 자동 실행 중지.
- **시험 실행**: 현재 문서의 모든 문제에 "대기열에 올림/대기/건너뜀 + 이유"(기존 문제·이미 알고 있음·중복 분석·AI 변경 24시간 제외·잘린 문서·AI 불필요·트리거 꺼짐·프로젝트 제외·한도 초과)를 보여 준다. "기존 문제도 새 문제인 것처럼" 옵션으로 실제 vault 에서 트리거 정책을 검증한다. 최근 판정 기록도 남는다.
- 아직 없음(v1.29): 실제 AI 호출, Claude 자동 사용 동의·엔진 선택·배터리 보류 UI, 결과 표시.
- 한계: 점검은 앱이 켜져 있을 때만, 꺼져 있던 동안의 변경은 다시 열 때 한 번 점검한다. 자동 관리를 끈 동안 생긴 문제는 켤 때 기준선이 된다. vault 를 삭제해도 자동 관리 저장소(작음)는 지우지 않는다.
