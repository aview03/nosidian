# PC 호스트 저장 계층 (v1.40)

설계: `docs/SYNC-HOST.md`. 이 문서는 **구현된 것**과 **한계**를 적는다. 쓰기 API(폰의 원격 쓰기)와 폰 Provider 는 v1.41~v1.42 이다.

## 구조
```
PC 앱(IndexedDB) ⇄ "내 PC 폴더" Provider(src/lib/sync/host.ts) ⇄ IPC(electron/hostIpc.cjs) ⇄ hostStore(electron/hostStore.cjs) ⇄ 호스트 폴더(평범한 파일 폴더)
```
- **새 동기화 엔진 없음**: 기존 `useApp.sync()`(받기 → 병합 → 올리기, `mergeNote`, 삭제·충돌 처리)가 그대로 쓴다. `Provider` 에 `baseRev`(PushChange)와 `afterSync`(ack) 두 개의 선택 항목만 더했고, 클라우드 Provider 는 무시한다.
- `RemoteCfg` 에 `HostCfg { kind: 'host', dir }` 추가. 로그인이 필요한 저장소는 `AccountKind`.
- 폴더 지정은 PC 에서 창으로 고른다. **공유 폴더(v1.38)와 겹치는 폴더는 지정할 수 없다**(양쪽 모두 검사), 드라이브 루트·홈 폴더·앱 데이터는 불가.

## 호스트 폴더 안
- 사용자 파일: 평범한 파일(.md·.docx …). 탐색기·다른 편집기로 열고 고칠 수 있다. 호스트는 **어떤 파일도 열거나 실행하지 않는다**(읽고 쓰기만).
- `.nosidian/` (숨김·목록·공유에서 제외): `manifest.json`(+`manifest.bak.json`) · `journal.json` · `tmp/` · `trash/` · `snapshots/<시각>/` · `host.lock` · `README.txt`(수정하지 말라는 안내).

## rev 와 manifest
- `rev = <epoch>-<gen>.<hash16>`. gen 은 경로별 단조 증가(내용 변경·삭제·재생성마다 +1), epoch 는 manifest 를 새로 만들 때 바뀐다. 그래서 A→B→A, 삭제 후 같은 내용 재생성, manifest 재생성 모두에서 옛 rev 와 같아지지 않는다.
- `manifest`: `files{path → gen, hash, size, mtimeMs, seq, by}`, `tombs{path → gen, seq, at, by}`, `devices{id → ackSeq, lastSeen}`, `trash[]`, 전역 `seq`.
- 삭제 기록(tombstone) rev 는 `<epoch>-<gen>.-`. 삭제 기록 위에 새로 만들려면 그 rev 를 baseRev 로 내야 한다 — PC 앱은 자신이 지웠음을 알므로 자동으로 내고, 다른 기기(v1.41)는 자신이 본 rev 만 쓸 수 있어 오래된 사본이 파일을 되살리지 못한다.

## 조건부·원자적 쓰기, 복구
- `put/del(path, baseRev)`: 현재 rev 와 같을 때만 반영, 다르면 아무것도 바꾸지 않고 409 + 현재 rev. 같은 이름(대소문자만 다름)·상위 경로·숨김·예약 이름·링크(심볼릭·정션)는 거절.
- 순서: ① `tmp` 에 쓰고 fsync → ② journal 기록 → ③ `rename` → ④ manifest 저장(백업 후 임시+rename) → ⑤ journal 삭제.
- 열 때 journal 로 복구: ③ 이 끝났으면 manifest 를 이어서 반영(롤포워드), 아니면 버림. 임시 파일 찌꺼기는 치운다. **저장 단계마다 끊어 보는 시험이 있다**(afterTmp·afterJournal·afterRename·afterManifest, 쓰기·삭제 모두).
- manifest 손상: 백업에서 되살린다(삭제 기록 포함, 손상본은 `manifest.corrupt-*` 로 남김). 백업도 못 쓰면 디스크를 깊게 스캔해 **새 epoch** 로 다시 만든다(`rebuilt`) — 옛 rev 를 가진 기기는 충돌로 보여 조용히 덮어쓰지 못한다.

## 외부 변경 감지
- 목록·읽기·동기화 때마다 스캔: 크기+mtime 이 같으면 건너뛰고 다르면 해시를 다시 계산 → 달라진 파일은 gen+1(`by: external`), 새 파일 추가, 사라진 파일은 삭제 기록. 읽기 직전에는 그 경로를 맞춰, 돌려주는 rev 가 항상 내용과 일치한다.
- 이동은 "삭제 + 새 파일"로 기록하고, 같은 내용이면 `moved` 힌트만 낸다(자동 처리 안 함). 앱이 꺼져 있는 동안의 변경도 다시 열 때 발견한다.

## 삭제·정리
- 삭제 = `.nosidian/trash/` 로 이동 + tombstone. 휴지통 파일은 90일 후 비운다. **tombstone 은 90일이 지났고 등록된 모든 기기가 확인(ackSeq ≥ tombstone.seq)했을 때만** 지운다(날짜만으로는 안 지운다). 기기를 해제하면 그 기기는 기다리지 않는다. 180일 이상 접속하지 않은 기기는 `staleDevices` 로 알린다(재연결 시 최초 연결과 같은 미리보기 — v1.42 에서 연결).
- PC 앱은 동기화가 끝날 때 `pc-app` 기기로 ack 한다(목록을 읽은 시점까지만 — 방금 쓴 변경은 다음 동기화에서 확인된다. 보수적인 동작).

## 최초 연결(미리보기 → 승인 → 스냅샷 → 반영) — `src/lib/hostConnect.ts`, `HostConnect.tsx`
1. 폴더 고르기 → 2. **미리보기**(읽기만): PC 앱에만 / 폴더에만 / 같음(해시) / 다름 / 노트가 아닌 파일 / 폴더에서 지워졌던 경로(되살아남 경고).
3. 내용이 다른 항목은 사용자가 **항목별로** 고른다(기본 선택 없음): PC 것 · 폴더 것 · 둘 다(폴더 것을 받고 PC 내용은 "(PC 사본)" 노트). 모두 고르기 전에는 시작할 수 없다.
4. 시작: **스냅샷 먼저**(`.nosidian/snapshots/` 에 호스트 파일 + manifest + PC 앱 Vault 노트 전체). 공간 부족·복사 실패면 **아무것도 하지 않고 중단**. 보관 최근 3개 또는 30일.
5. 올리기·받기 → 앱 상태 반영 → 이후는 기존 동기화. **삭제는 없다.** 중간에 실패하면 PC 앱의 노트는 바뀌지 않는다(호스트에 이미 올라간 새 파일은 남는다 — 지우지 않는다).
- 되돌리기: "폴더 연결 끊기"(노트·폴더 파일 모두 그대로) · "스냅샷에서 복원"(PC 앱 노트 내용을 스냅샷대로).

## 한계·미확인
- **스캔은 메인 프로세스에서 동기적으로** 돈다 — 파일이 아주 많은 폴더(수만 개)에서는 화면이 잠깐 멈출 수 있다. 빠른 점검은 크기+mtime 이 같으면 내용이 바뀐 것을 못 본다(깊은 점검은 있으나 자동으로 돌리지 않는다).
- 다른 프로그램이 파일을 열어 둔 채 잠그고 있으면(Windows) 쓰기(rename)가 실패할 수 있다 — 오류로 알리지만 재시도는 없다.
- 줄바꿈(CRLF↔LF)만 다른 노트도 "내용이 다름"으로 본다.
- 최초 연결은 노트(.md)만 내용을 비교한다. 일반 파일은 폴더 쪽 목록만 보이고 PC 쪽에는 원본이 없다.
- 스냅샷은 파일을 그대로 복사한다(중복 제거 없음) — 큰 폴더는 공간을 많이 쓴다.
- 휴지통에서 되살리는 화면은 **v1.43.6 에서 만들었다**: 저장 계층 `trashList()`·`restoreTrash(name)`(원래 자리가 비어 있으면 거기로 — 삭제 기록 위에 쓰는 것이라 그 rev 를 baseRev 로 —, 이미 다른 파일이 있으면 덮어쓰지 않고 `이름 (복구).확장자`·`(복구 2)`…), IPC `host:trash`·`host:restore`, PC 앱 설정 > 노트와 동기화 > 고급 > "휴지통 (n)"(`HostTrash.tsx`). 정리(gc)는 동기화가 끝날 때 조용히 돈다.
- 창에서 폴더를 고르는 대화상자(공유 폴더와 겹침 거절 포함)는 자동 시험하지 못했다(`overlaps` 판별만 시험).
- 원격(폰) 쓰기·`ack`(폰)·실행 파일 쓰기 거부는 v1.41 에서 서버에 연결했다(`docs/HOST-SERVER.md`).
