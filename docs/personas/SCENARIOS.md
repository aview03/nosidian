# 페르소나별 시나리오

각 시나리오는 **공통 흐름(C1~C10)** 위에 **역할별 차이(P)** 를 얹은 하루 흐름이다. 단계마다 [기대 결과]와 [점검 질문(README)]을 본다. "자동"은 CDP 로 재현 가능, "눈"은 사람이 판단.

## 공통 흐름
| # | 단계 | 기대 결과 | 층 |
| --- | --- | --- | --- |
| C1 | 첫 실행: 언어 → 이름 → 역할 선택 → 시작 방식(예제 노트/빈 vault) | 역할이 "내 업무" 구성에 반영된다. 한 화면에 한 가지만 묻는다 | 자동+눈 |
| C2 | 홈("내 업무") 확인 | 그 역할이 매일 보고 싶은 타일이 보이고, 비어 있으면 이유를 안다 | 자동+눈 |
| C3 | 노트 쓰기(메모 탭 → 새 노트 → 저장) | 어디에 저장되는지, 폴더를 만들고 옮기는 법을 헷갈리지 않는다 | 눈 |
| C4 | 일정 추가("내일 3시 치과"처럼 말하듯) | 입력이 일정이 되고 캘린더에 보인다. 실수하면 고치기·지우기가 쉽다 | 자동+눈 |
| C5 | 프로젝트 만들기(템플릿) → 업무 추가·완료 | 허브(할 일/보드/문서/타임라인)가 이해된다 | 눈 |
| C6 | 다른 화면으로 갔다가 **뒤로**(설정·노트·검색·캘린더·허브) | 온 곳으로 돌아간다 | 자동(폰 실제 뒤로 키) |
| C7 | 폰과 맞추기("내 PC" 동기화 / 클라우드) | 연결 코드는 요청할 때만 모달, 연결되면 자동으로 닫힘, 기기 목록에서 해제 | 자동+폰 |
| C8 | AI 연결(구독/내 컴퓨터/API 키) 여러 개, 패널에서 `연결 › 모델` 고르기 | 하나만 연결되는 것처럼 보이지 않는다 | 자동+눈 |
| C9 | AI 에게 묻기 → 변경 제안 승인/거절 | 읽기 전용(묻기)과 변경 제안의 차이를 안다. 승인 없이는 아무것도 바뀌지 않는다 | 눈 |
| C10 | 설정 변경(이름·역할·화면) 후 홈 확인 | 바꾼 설정이 화면에 바로 반영된다 | 자동+눈 |

## 역할별 차이(P)
각 역할의 시작 타일은 `src/lib/persona.ts` 의 `PERSONA_INFO` 기준이다.

### 디자이너 — 시안·리뷰·피드백 (타일: 오늘 · 오늘 마감 · 기다리는 일 · 프로젝트)
- P1: "시안 v2 피드백 대기" 같은 업무를 `waiting` 으로 만들고 **기다리는 일** 타일에 뜨는지(C5).
- P2: 리뷰 노트에 이미지를 붙이고(메모/노트), 피드백을 링크로 잇는다(C3).
- P3: 오늘 마감 시안을 홈에서 완료 처리한다(C2).
- 눈: "기다리는 일"이 무슨 뜻인지 디자이너 말로 이해되는가.

### 기획자 — 결정·정책·일정 (타일: 오늘 · 결정 · 기한 지난 · 기다리는 일 · 프로젝트)
- P1: 결정 안건(`kind:decision`)을 만들고 **닫을 때 결론을 반드시 적는** 흐름(C5).
- P2: 문서 규칙 켜기 → "문서 점검" 탭에서 경고를 보고 AI 로 고치기 제안 → 승인(C9).
- P3: 회의록 → 업무 쪼개기(받은 업무 정리).
- 눈: "결정/미결" 용어, 규칙이 사람 문서를 막지 않는지(경고만).

### 개발자 — 개발·기록·이슈 (타일: 오늘 · 진행 중 · 기한 지난 · 새 업무(정리 전) · 프로젝트)
- P1: 이슈를 빠르게 모아 "받은 업무 정리"에서 프로젝트로 넣는다(C5).
- P2: 코드 블록이 있는 기록 노트, 백링크로 이슈-기록 연결(C3).
- P3: AI 패널에 로컬 모델(Ollama) 연결 → 코드/노트 요약 질문(C8, C9).
- 눈: 코드 블록 복사, 마크다운 문법 도움.

### 마케터 — 캠페인·콘텐츠 일정 (타일: 오늘 · 이번 주 · 오늘 마감 · 기다리는 일 · 프로젝트)
- P1: 반복 일정(주간 콘텐츠 발행)과 기간 일정(캠페인 2주)을 만든다(C4).
- P2: 캘린더 월/주/목록 전환, 위젯으로 일정 확인(폰).
- P3: 프로젝트 타임라인으로 캠페인 흐름 보기(C5).
- 눈: 반복·기간 입력 UI 가 모바일에서 손에 닿는가.

### 연구자 — 읽기·실험·아이디어 (타일: 오늘 · 진행 중 · 오늘 마감 · 새 업무 · 프로젝트)
- P1: 읽은 자료 노트를 만들고 `[[링크]]` 로 아이디어 노트와 잇는다. 백링크·그래프로 관계 보기(C3).
- P2: 검색(Ctrl+Shift+F, 모바일 검색 탭)으로 예전 노트 찾기. 검색어를 쓴 뒤 노트를 열었다가 **뒤로** 와도 결과가 남는지(C6).
- P3: PC 폴더 보기로 논문 PDF 를 폰에서 받기(C7, 파일).
- 눈: 그래프가 많은 노트에서 읽기 쉬운가.

### 학생 — 수업 필기·과제 마감 (타일: 오늘 · 이번 주 · 오늘 마감 · 기한 지난)
- P1: Daily 노트에 수업 필기, 체크박스로 과제 마감을 적는다(C3, C4).
- P2: 폰에서 빠르게 입력(캘린더 하단 입력창 "내일 3시 과제") 후 PC 와 맞추기(C4, C7).
- P3: 홈에서 이번 주 마감 확인, 지난 일 처리(C2).
- 눈: 프로젝트가 없는 사람에게 "프로젝트" 개념을 강요하지 않는가(학생은 시작 타일에 프로젝트가 없다).

## 시나리오 실행 기록 방식
`FINDINGS.md` 의 표에 시나리오·단계·결과(확인함/못 함)·불편(있으면 영향·제안)을 적는다.
