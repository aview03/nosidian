# 페르소나별 통합 시험과 사용성 점검

> 목적: 역할(디자이너·기획자·개발자·마케터·연구자·학생)별로 **하루 흐름 시나리오**를 짜서 앱을 끝까지 써 보고, "그 역할의 **일반적인 사람**이라면 불편하지 않을까?"를 단계마다 묻는다. 불편은 `docs/NEXT-SESSION.md` §5.5 처럼 버그/UX 항목으로 올린다.
> 시나리오: `SCENARIOS.md` · 점검 결과: `FINDINGS.md` · 역할 정의: `src/lib/persona.ts`, `docs/UX-PERSONAS.md`.

## 방법
1. **자동 층(재현 가능한 부분)**: CDP 로 실제 앱을 조작해 단계를 재현하고 화면 텍스트·스크린샷을 남긴다. 지금 있는 것 — `scripts/dev/persona-first-run.sh <역할> <이름>`: 새 시험 프로필로 온보딩(역할 선택) → 예제 노트 → 내 업무 화면을 캡처(6역할을 돌려 비교). 환경변수 `SCRATCH` 에 결과 폴더를 지정한다.
2. **사람 눈 층**: 각 단계마다 아래 점검 질문으로 사용성을 판단해 `FINDINGS.md` 에 적는다. 자동으로 판단할 수 없는 항목(용어가 어려운가, 다음에 뭘 눌러야 하는지 보이는가)이다.
3. 폰은 시험 기기라 데이터를 덮어써도 된다. 폰 단계는 **먼저 사용자에게 잠금 해제를 요청**한다. 홈 화면 위젯 선택 UI 는 자동화하지 않는다.

## 점검 질문(모든 단계 공통)
- **알아볼 수 있나**: 지금 무엇을 해야 하는지, 다음에 누를 곳이 보이는가? 이름(용어)이 이 역할의 말인가?
- **되돌릴 수 있나**: 실수하면 취소·뒤로가 같은 곳으로 돌아가는가(`docs/NEXT-SESSION.md` §5.5-7 의 규칙)? 지우기·덮어쓰기 전에 확인이 있는가?
- **빈 상태**: 데이터가 없을 때 무엇을 보여 주는가? 왜 비었는지 설명하는가?
- **손이 닿나(모바일)**: 엄지로 닿는 곳에 주요 버튼이 있는가? 입력 칸·버튼 간격이 충분한가?
- **기본값**: 기본 설정이 안전하고 이 역할에 맞는가? 한 번에 너무 많이 묻지 않는가?
- **우리 UX 선호(§3-7)**: 밀도 낮게, 직관적 이름, 모호한 입력 금지, PC 전용 항목은 모바일에서 숨김.

## 보고 형식(이 프로젝트 규칙)
단계마다 **확인한 것 / 못 한 것**을 분리해 적는다. 자동 재현하지 못한 단계를 "확인됨"으로 쓰지 않는다.
