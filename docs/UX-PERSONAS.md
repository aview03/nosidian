# 사용자 페르소나와 시나리오 (v1.30 UX 개편의 기준)

목적: 기능을 더하는 대신, **누가 어떻게 쓰는지**에 맞춰 첫 화면·설정·AI 연결의 구조를 정한다. 아래 페르소나는 가설이며, 실제로 쓰는 모습을 보면서 고친다.

## 공통 원칙
1. 처음 5분 안에 "내 노트가 생겼고, 오늘 할 일이 보인다"까지 간다. 동기화·AI·규칙은 나중에.
2. 용어는 사용자의 목표로 말한다("기기끼리 맞추기", "AI 연결"). 기술 용어(WebDAV·MCP·CLI·엔드포인트)는 "고급" 안에서만.
3. 켜 둔 것은 위, 안 쓰는 것은 아래. 비슷한 것끼리 묶는다.
4. 모바일에서 의미 없는 것(단축키, PC 전용 AI)은 보이지 않는다.
5. 페르소나는 **기본값**을 바꿀 뿐이다. 모든 기능은 누구에게나 열려 있다.

## 페르소나 6명

### 1. 디자이너 — "민서, 프로덕트 디자이너 (3년차)"
- **하는 일**: 화면 시안 작업, 디자인 리뷰, 개발과 피드백 주고받기, 디자인 시스템 문서.
- **노트 쓰는 순간**: 리뷰 회의 메모, 피드백 정리, 레퍼런스 링크 모음, 시안별 결정 기록.
- **필요**: 마감 임박 작업 한눈에, 피드백 대기 중인 일(내가 기다리는 것), 프로젝트별 문서, 이미지 붙여넣기.
- **불필요**: 코드·Git 용어, 문서 규칙 엔진, MCP.
- **하루 시나리오**: 아침에 오늘 할 일과 마감을 보고 → 리뷰 회의 중 폰으로 한 줄 메모 → 오후에 피드백 대기 중인 항목을 확인하고 재촉 → 저녁에 결정된 것을 프로젝트 노트에 기록.
- **홈(내 업무) 기본**: 오늘 · 마감 임박 · 기다리는 일 · 프로젝트
- **동기화**: Google Drive/OneDrive(회사 계정). GitHub 토큰은 낯설다.
- **AI**: 거의 안 씀. 쓴다면 "회의 메모 요약". → 설정에서 AI는 접혀 있어도 된다.

### 2. 기획자 — "지우, 서비스 기획자 (5년차)"
- **하는 일**: 요구사항·정책 정리, 이해관계자 조율, 결정 사항 추적, 일정 관리.
- **노트 쓰는 순간**: 회의록, 결정 기록, 정책 문서, 요구사항 목록.
- **필요**: "결정할 일" 모음, 기한 지난 일, 기다리는 일, 프로젝트별 상태, **문서 규칙·점검**(중복·충돌 문서가 곧 사고), AI 로 문서 점검·정리.
- **불필요**: 코드 관련 개념.
- **하루 시나리오**: 결정 대기 항목과 기한 지난 일을 확인 → 회의록 작성(결정 필요 표시) → 정책 문서가 늘어날 때 점검 → 문서 규칙이 켜진 프로젝트에서 새 문제 알림 → AI 분석 결과 확인 후 변경 제안 승인.
- **홈 기본**: 오늘 · 결정할 일 · 기한 지난 일 · 기다리는 일 · 프로젝트
- **동기화**: 팀 공유(Drive/OneDrive 또는 GitHub).
- **AI**: 문서 점검 → AI로 고치기, 자동 분석(선택). 가장 "AI 자동 문서 관리" 의 핵심 사용자.

### 3. 개발자 — "태오, 백엔드 개발자 (7년차)"
- **하는 일**: 기능 개발, 코드 리뷰, 기술 문서·ADR, 장애 대응 기록.
- **노트 쓰는 순간**: 설계 메모, 디버깅 기록, 회의 메모, 할 일(이슈 같은 것), README 초안.
- **필요**: Markdown 그대로(소스 모드), 키보드 중심, GitHub 동기화, 코드 블록, 진행 중인 일, 받은 업무(이슈 수집).
- **불필요**: 과한 안내, 둥근 UI 설명.
- **하루 시나리오**: 오늘 할 일·진행 중인 일 확인 → 설계 노트 작성(링크로 연결) → AI 에게 "이 노트 요약/관련 노트 찾기" → 외부 AI(Claude Code 등)가 노트를 읽고 변경안을 내면 승인.
- **홈 기본**: 오늘 · 진행 중 · 기한 지난 일 · 받은 업무 · 프로젝트
- **동기화**: GitHub.
- **AI**: Claude Code CLI(이미 로그인됨) 또는 로컬 Ollama. API 키도 가능. MCP(외부 AI 연결)를 이해하는 유일한 층 → "고급"에 두되 개발자가 쉽게 찾게.

### 4. 마케터 — "하은, 퍼포먼스 마케터 (4년차)"
- **하는 일**: 캠페인 기획·집행, 성과 보고, 콘텐츠 일정, 대행사 조율.
- **노트 쓰는 순간**: 캠페인 브리프, 주간 성과 메모, 콘텐츠 캘린더, 아이디어 모음.
- **필요**: **일정(캘린더)**·이번 주 할 일, 마감 임박, 기다리는 일(대행사 회신), 템플릿(브리프·보고).
- **불필요**: 문서 규칙, 그래프, 개발 용어.
- **하루 시나리오**: 이번 주 일정과 마감을 보고 → 콘텐츠 발행 일정 추가(오늘 일정 빠른 입력) → 성과 메모 작성 → 대행사 회신 대기 확인.
- **홈 기본**: 오늘 · 이번 주 · 마감 임박 · 기다리는 일 · 프로젝트
- **동기화**: Google Drive/OneDrive.
- **AI**: 쓴다면 문장 다듬기·요약. 복잡한 연결은 못 한다 → 한 번 클릭으로 되는 방식이 있어야 함(지금은 불가능 — 아래 AI 연결 참고).

### 5. 연구자 — "도윤, 대학원 연구원"
- **하는 일**: 논문 읽기, 실험 기록, 아이디어 정리, 문헌 관리, 학회 마감.
- **노트 쓰는 순간**: 논문 읽기 노트, 실험 로그, 연구 아이디어(떠오른 순간), 참고문헌 연결.
- **필요**: **노트 간 연결(링크·그래프)**, 빠른 캡처, 검색, 진행 중인 연구, 학회·제출 마감, 수식·코드 블록.
- **불필요**: 협업 기능 일부(결정할 일, 담당자 없는 일).
- **하루 시나리오**: 아이디어를 폰으로 즉시 메모 → 논문 노트에 [[링크]]로 연결 → 그래프로 관련 개념 확인 → 마감 있는 일 확인.
- **홈 기본**: 오늘 · 진행 중 · 마감 임박 · 받은 업무(아이디어 수집) · 프로젝트
- **동기화**: Google Drive 또는 GitHub.
- **AI**: 요약, 관련 노트 찾기. 데이터 외부 전송에 민감 → **로컬 모델(Ollama)** 선호. 설정에서 "내 컴퓨터에서 돌리는 AI"가 먼저 보여야 함.

### 6. 학생 — "서연, 대학생"
- **하는 일**: 수업 필기, 과제·시험 일정, 팀 프로젝트, 공부 정리.
- **노트 쓰는 순간**: 강의 필기, 과제 메모, 시험 범위, 팀플 회의.
- **필요**: **오늘 할 일·이번 주 마감**, 캘린더(시험·과제), 빠른 필기, 무료로 동작.
- **불필요**: 프로젝트 허브·규칙·담당자 개념, 결정할 일.
- **하루 시나리오**: 아침에 오늘 수업과 마감을 보고 → 수업 중 폰/노트북으로 필기 → 밤에 과제 마감 확인 → 주말에 한 주 정리.
- **홈 기본**: 오늘 · 이번 주 · 마감 임박 · 기한 지난 일 (프로젝트·결정·기다림은 꺼짐)
- **동기화**: Google Drive/OneDrive(학교 계정). 비용 부담 큼.
- **AI**: 유료 구독 없음 → 없거나 로컬 모델. AI 설정은 "나중에".

## 페르소나가 바꾸는 것 / 바꾸지 않는 것
- 바꾼다(v1.30 범위 a): 내 업무 홈의 **처음 타일 구성**, 첫 노트 템플릿 제안, 온보딩 이후 "다음에 해 볼 일" 안내 순서(동기화/AI 를 먼저 권할지).
- 바꾸지 않는다: 기능의 유무. 설정에서 언제든 "내 업무 구성 다시 고르기".
- 이후(범위 b, 실사용을 본 뒤): AI 빠른 질문 문구, 템플릿 추천 폭 확대.

## 검증 방법
- 페르소나마다 "5분 시나리오"를 직접 따라 하며(예제 vault + 새 vault) 막히는 곳을 기록한다.
- 설정 개편 전후로 "AI 연결까지 몇 번 누르는가", "동기화 연결까지 몇 단계인가"를 센다(현재 → 목표).
