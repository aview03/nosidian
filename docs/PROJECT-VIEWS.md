# 프로젝트 보기 확장 설계 (UI/UX)

> 상태: **설계 확정(§8 권장값 4가지 모두 채택, 2026-11-11) · 1·2·3단계 구현·PC 앱 확인 완료**(1: `보기` 탭+칩 줄·마지막 보기 기억 / 2: **표**·**담당자별**·공통 `되돌리기` 알림 / 3: **간트** — `start:` 토큰·편집기 `시작일`·막대·마름모·주/월 눈금·묶기(없음/담당자/상태)·PC 끌기(이동·양 끝 조절·Alt+방향키)·폰은 탭→편집기). 폰은 실기기가 아니라 400px 에뮬레이션으로만 봄 — 실기기 미확인.
> 2단계에서 정한 것: 필터 줄(`내 것만`(내 이름이 있을 때만)·`완료 포함`)은 표·담당자별에만 보임, 상태 정렬은 진행 중→대기→할 일→완료, 빈 값(마감·담당·우선순위 없음)은 정렬 방향과 상관없이 맨 뒤, 여러 명이 맡은 일은 담당자별에서 맡은 사람마다 나오고 표에서는 편집기로 바꿈. 끌어 옮기면 담당은 그 사람 한 명으로 바뀜(알림에 표시).
> 알려진 아쉬움: 폰에서 표 한 장이 3줄(상태·담당·마감·우선 칩이 한 줄에 안 들어감), 표에서 마감·상태를 고치면 정렬 때문에 그 줄이 곧바로 다른 자리로 움직임(알림으로 알려 주고 되돌리기 가능). 사용자 결정(2026-11-11): 간트는 칸반 보드처럼 도입, 표·담당자별·결정 기록·우선순위×마감 매트릭스 도입, 진행률 번다운은 추후.
> 대상 화면: 프로젝트 허브(`ProjectHub.tsx`) — PC(Electron)와 폰(Capacitor).

## 1. 설계 원칙 (사용자 경험을 해치지 않기 위한 것)
1. **같은 데이터, 다른 눈**: 모든 보기는 노트 속 체크리스트 줄(`due/owner/p/status/kind`)을 읽고, 고칠 때는 그 줄을 고친다. 보기마다 별도 데이터가 없다. (다른 도구로 열어도 깨지지 않는다)
2. **익숙한 것은 그대로**: 지금 `할 일`·`보드`·`타임라인`을 쓰는 사람은 **탭 한 번**으로 예전과 같은 화면에 닿아야 한다. 늘어난 보기가 첫 화면을 어지럽히면 안 된다.
3. **모든 보기에서 같은 동작**: 카드·행을 누르면 같은 업무 편집기가 열린다. 상태 색·아이콘·마감 표시 모양이 같다.
4. **데이터가 없으면 이유와 다음 행동을 보여 준다**(빈 화면 금지). 예: 간트는 "마감일이 있는 업무가 없어요 [업무 추가]".
5. **폰이 기준**: 360px 폭에서 가로 스크롤은 **간트와 보드에서만**, 그 외는 세로 스크롤만. 터치 목표 44px 이상.
6. **고급 기능은 접어 둔다**: 시작일 같은 선택 항목은 `더 보기` 안에(이미 TaskEditor 의 `showAll/more` 방식).
7. 색만으로 뜻을 전하지 않는다(상태는 아이콘·글자 병행), 다크 테마·움직임 줄이기 설정 존중.

## 2. 내비게이션: 탭 구조

### 문제
지금 탭 5개(`할 일 · 보드 · 타임라인 | 문서 · 문서 점검`)에 7개 보기를 더하면 12개가 되어 폰에서 탭 줄이 가로로 길게 스크롤된다.

### 안 (권장): 1단 탭은 4개, 보기는 "보기" 안의 선택 줄
```
┌──────────────────────────────────────────┐
│ ← 행사 준비                       ＋  ⋯ │
│ [상태 진행] [담당 민수] [마감 12-20] …   │
│  할 일 │ 보기 ▾ │        문서 │ 문서 점검 │   ← 1단 탭(4개)
│ ─────────                                │
│ ( 보드 )( 간트 )( 타임라인 )( 표 )( 담당자 )( 매트릭스 )( 결정 )  ← 보기 칩(가로 스크롤)
│                                          │
│  … 선택한 보기 …                          │
└──────────────────────────────────────────┘
```
- `보기` 탭 이름은 **현재 보기 이름을 보여 준다**: `보기 · 보드`. 탭을 누르면 마지막에 쓴 보기가 바로 열린다(칩 줄은 그 보기 위에 항상 보인다).
- **마지막으로 쓴 보기를 프로젝트별로 기억**한다(없으면 `보드`). 기존 `보드` 사용자는 그대로 `보기`를 한 번 눌러 같은 화면에 닿는다(= 한 탭 늘지 않음).
- 데스크톱은 칩이 모두 보이고, 폰은 가로 스크롤(끝이 잘려 보이게 해서 더 있음을 암시, 선택된 칩은 자동으로 화면 안으로).
- 키보드: 탭·칩 모두 좌우 화살표로 이동(`role="tablist"`).
- 대안(탭 7~8개 평면 나열)은 폰에서 현재 탭 줄 스크롤이 더 길어지고 "문서" 그룹과 섞여 기각.

### 칩 이름과 순서 (평이한 말, 자주 쓰는 순)
`보드 · 간트 · 타임라인 · 표 · 담당자별 · 매트릭스 · 결정`
- 길게 눌렀을 때/데스크톱 툴팁: 한 줄 설명(예: 매트릭스 — "중요한 일과 급한 일을 한눈에").
- `타임라인`(날짜별 목록)과 `간트`(막대)는 이름 아래 설명으로 구분한다.

## 3. 공통 요소
- **필터 줄**(칩 줄 아래 한 줄, 보기별로 쓸 수 있는 것만): `내 것만 / 전체`(홈과 같은 용어), `완료 포함` 토글. 선택은 보기를 바꿔도 유지된다.
- **업무 카드 공통 모양**: 상태 아이콘 · 제목 · 마감(지났으면 빨강+`N일 지남`) · 담당 약어 · 우선순위 점. 길면 두 줄까지 말줄임.
- **실행 취소**: 보기에서 일어난 모든 변경(끌어놓기 포함)은 알림줄에 `되돌리기`를 달아 5초간 둔다(기존 보드 끌어놓기에도 같은 규칙 적용 권장).
- **로딩·빈 상태**는 보기마다 아래 §4 에 적는다.

## 4. 보기별 설계

### 4.1 간트 (칸반처럼 "보고 + 바로 고치는" 보기)
```
            11월                     12월
         17 18 19 20 21 22 23 …  1  2  3
행사장 예약  ▓▓▓▓▓▓▓│                       ← 막대(시작~마감), 진행 중=채움
케이터링     ·····▓▓▓▓▓▓▓▓                  ← 대기=빗금
현수막 인쇄          ◆                       ← 마감일만 있음 = 마름모(막대 아님)
                     ┆ 오늘(세로선)
── 일정 없음 (3) ────────────────
 포스터 시안 · 정산 · …
```
- **데이터**: 막대 = `시작일 ~ 마감`. 시작일은 새 선택 토큰 `start:YYYY-MM-DD`(없으면 마감일에 **마름모 한 점**으로 그려 "기간을 모른다"를 정직하게 표시). 일정(`@날짜 end:`)이 붙은 업무는 그 범위를 막대로 쓴다. 마감도 시작도 없으면 맨 아래 `일정 없음`.
- **프로젝트 마감**은 맨 위 깃발 한 줄.
- **배치**: 왼쪽 라벨 열(폰 112px, PC 220px)은 **고정**, 오른쪽 날짜 영역만 가로 스크롤. 열린 일만 기본, `완료 포함` 켜면 흐리게.
- **눈금**: 두 단계 `주 / 월`(분절 스위치). 기본은 **오늘이 왼쪽에서 25% 지점**에 오는 주 단위. 열자마자 오늘로 스크롤. 오늘 세로선·주말 옅은 띠.
- **상태 표현**: 할 일=테두리만, 진행=채움, 대기=빗금, 지난 마감=빨간 윤곽+`!`, 완료=회색 취소선 라벨. 색 + 무늬 병행.
- **정렬/묶기**: 기본은 시작일 순. `묶기: 없음 / 담당자 / 상태`.
- **조작**
  - 공통: 막대·라벨 탭 → 업무 편집기. 편집기에 `시작일`이 `더 보기`로 접혀 있다가 간트에서 열면 펼쳐진다.
  - PC: 막대 **가운데를 끌면 이동(시작·마감 같이), 양 끝을 끌면 기간 조절**, 하루 단위로 달라붙음. 놓으면 줄이 고쳐지고 `되돌리기` 알림.
  - 폰: 막대 끌기는 가로 스크롤과 충돌하므로 **끌기를 막고** 탭 → 편집기(날짜 선택기). (칸반은 길게 눌러 끄는 방식이 이미 있으나, 간트는 스크롤 영역이 넓어 오조작 위험이 커서 제외)
- **빈 상태**: "마감일이 있는 업무가 없어요. 업무에 마감일을 넣으면 여기에 막대로 나타나요. [업무 추가]".
- **의존관계(앞선 일)**: 이번 범위에서 제외. 막대 사이 화살표는 나중(`after:` 토큰) — 문서에 한계로 적는다.

### 4.2 표
```
 제목 ▾          상태    담당   마감    우선
 행사장 예약     진행    민수   11-20   ●●●
 현수막 인쇄     할 일   —      11-22   ●●
```
- 열: `제목 · 상태 · 담당 · 마감 · 우선순위`(+ 시작일 있으면 `시작`). 머리글을 누르면 정렬(▲▼), 기본 정렬은 마감 빠른 순·우선순위 높은 순.
- **셀 편집은 작은 선택창**(상태/담당/마감/우선순위를 눌러 고르기). 자유 입력 셀·열 추가는 하지 않는다(스프레드시트가 되면 복잡해짐).
- **폰**: 표 대신 **두 줄 카드 목록**으로 바꿔 그린다(1줄 제목, 2줄 상태·담당·마감·우선). 정렬은 상단 `정렬 ▾` 하나로.
- 행 길게 누름/오른쪽 끝 `⋯`: 완료 처리·삭제 등 기존 업무 메뉴.
- 빈 상태: 기존 할 일 탭과 같은 문구.

### 4.3 담당자별
```
 민수 (나)        열린 5 · 진행 2 · 지남 1 ▓▓▓▓▓▓░░
   ▸ 행사장 예약  … 
 지은             열린 2 · 진행 1        ▓▓░░░░░░
 ⚠ 담당 없음      열린 3                  ← 맨 위로 강조(담당 정하기 안내)
```
- 사람마다 한 구역(접고 펼 수 있음). 머리줄에 **열린 일 수·진행·마감 지남**과 **업무량 막대**(가장 많은 사람 = 100%). 사람 평가처럼 보이지 않게 숫자만, 순위·색 비교는 하지 않는다.
- 순서: **나 → 담당 없음(경고 강조) → 나머지 가나다**. 구역은 처음엔 `나`와 `담당 없음`만 펼침.
- 업무 한 줄은 공통 카드. **다른 사람 구역으로 끌어 놓으면 담당 변경**(PC), 폰은 탭 → 편집기. 놓으면 `되돌리기`.
- 사람이 한 명도 없으면: "담당자를 정하면 사람별로 모아 보여요(업무의 `owner`)".

### 4.4 결정 기록
- 대상: `kind: decision`(결정 안건)인 업무. 두 구역: **결정할 일**(열림) → **결정함**(완료, 결론 포함).
- 카드: 제목 · 영향(`impact`) · **결론(`conclusion`)을 인용 스타일로 그대로** 보여 줌. 결정함은 가장 최근 마감/수정 순(완료 시점 기록이 없으므로 마감 기준임을 정렬 이름에 명시).
- 상단 `결정 추가` 버튼(결정 안건 모양으로 편집기를 열어 줌).
- 빈 상태: "아직 결정 안건이 없어요. 정해야 할 일이 생기면 '결정 추가'로 기록해 두세요 — 나중에 왜 그렇게 정했는지 찾을 수 있어요".
- 노트로 내보내기(결정 기록 문서 한 장 만들기)는 후속 아이디어, 이번 범위 밖.

### 4.5 우선순위 × 마감 매트릭스
```
                 급함(7일 이내·지남)   덜 급함
  중요(p1·p2)   ┌ 지금 하기 ┐        ┌ 계획하기 ┐
  덜 중요        └ 빨리 처리 ┘        └ 나중에   ┘
   ⓘ 우선순위나 마감이 없는 일 4개 — [정하러 가기]
```
- 전문 용어(아이젠하워) 대신 **행동 이름** 4개: `지금 하기 / 계획하기 / 빨리 처리 / 나중에`.
- 기준: 중요 = 우선순위 1·2, 급함 = 마감이 오늘+7일 이내이거나 지남. 우선순위 없음 = 덜 중요, 마감 없음 = 덜 급함. **이 기준은 화면에 한 줄로 보여 준다**(투명하게). 기준값은 설정 없이 고정(나중에 필요하면 조절).
- 우선순위·마감이 비어 모두 `나중에`로 쏠려 보이는 문제를 막기 위해 **"정하지 않은 일 N개"** 칸을 따로 두고 편집기로 연결.
- 폰: 2×2 격자는 칸 안에 **개수 + 상위 2개 제목**만, 칸을 누르면 그 칸의 전체 목록이 시트로 열림.
- 이번 범위는 **읽기 중심**(끌어서 칸 이동은 마감·우선순위 중 무엇을 바꿀지 모호해 제외).

## 5. 접근성·테마·언어
- 모든 칩·막대·카드는 키보드로 초점이 가고 `aria-label`(제목·상태·마감)을 가진다. 간트 막대는 목록 의미(`role="list"`)로 읽히게 하고, 화면낭독용 표 대안은 표 보기가 제공.
- 색 대비 4.5:1 이상, 다크 테마 토큰 사용, 움직임 줄이기 설정이면 스크롤·끌기 애니메이션 없음.
- 문구는 모두 `t()` + `en.ts` 에 추가.

## 6. 성능·한계
- 업무 500개까지 한 번에 그린다(간트 행·표 행은 화면 밖 줄이면 그리지 않는 단순 윈도잉, 그 이상은 후속).
- 간트 의존관계, 진행률 번다운(완료 시점 미기록), 표 열 추가·셀 직접 입력, 매트릭스 끌어 옮기기는 이번 범위 밖.

| 1 | `보기` 탭 + 칩 줄 껍데기(기존 `보드`·`타임라인` 옮김), 마지막 보기 기억 | 기존 사용자의 보드가 한 탭 안에 그대로 열림, 폰 360px |
| 2 | **표**·**담당자별**(데이터 이미 있음) | 정렬, 셀 선택창, 끌기 담당 변경, 되돌리기 |
| 3 | **간트**: `start:` 토큰·편집기 `시작일`·막대·눈금·PC 끌기 | 하루 단위 붙기, 폰은 탭만, 오늘 자동 스크롤 |
| 4 | **결정 기록**·**매트릭스** | 기준 표시, 빈 상태 |
| 5 | 페르소나 시나리오 점검(기획자 P1~P3·마케터·개발자) + 폰 실기기 | `docs/personas` 에 결과 |

## 8. 결정이 필요한 것 (권장값 포함)
1. **탭 구조**: `보기` 안에 칩으로 묶기(권장) vs 탭 평면 나열.
2. **시작일 토큰**: `start:YYYY-MM-DD`(권장). 빠른 입력의 "11월 20일부터 12월 3일까지"가 업무일 때 시작·마감으로 들어가게 할지(권장: 예).
3. **매트릭스 기준**: 중요=우선순위 1·2, 급함=7일 이내(권장).
4. **간트 폰 끌기**: 제외하고 편집기 날짜 선택만(권장).

## 9. 실기기 확인 (2026-11-11, Galaxy S23+ R3CTC0DVCTX, 실제 터치 `adb input`)
**확인함**
- `보기` 탭·칩 줄: 칩 5개가 폰 폭(384px)에 들어가고, 선택한 칩은 자동으로 화면 안으로 스크롤됨.
- 간트: 막대·마름모·오늘 선·주말 띠 표시. **막대 위에서 스와이프하면 막대가 움직이지 않고 가로 스크롤만 됨(노트 그대로, 편집기 안 열림)**. 막대를 탭하면 편집기가 열리고 마감·시작일이 채워져 있음. 시작일 `×` → 저장하면 `start:` 만 지워지고 `due:` 는 그대로.
- 표: 상태 칸을 누르면 하단 시트가 뜨고 선택하면 노트가 바뀌며 `되돌리기` 알림이 뜸. **알림은 5초 뒤 사라지고(사람이 읽고 누르기에 빠듯할 수 있음), 5초 안에 누르면 원래대로 복원됨.**
- 담당자별: 구역(담당 없음 강조·민수·지현)과 열린/진행/지남 수·업무량 막대 표시.
**실기기에서만 보인 문제 → 수정**: 안드로이드 날짜 입력이 `2026. 11. 12.` 형식이라 표의 마감 칸(136px)이 `2026. 1…` 로 잘림 → 폰 폭에서 최소 168px(남는 폭 사용)로 넓힘(측정: 219px, 잘림 없음. 시각 재확인은 화면 잠금으로 보류).
**확인하지 못함**: 안드로이드 날짜 선택기에서 날짜를 골라 저장하는 것, 담당자별 끌어놓기(터치로는 불가·PC 전용), 업무가 많을 때의 간트 스크롤 성능, `되돌리기` 5초가 충분한지에 대한 사용자 의견.
