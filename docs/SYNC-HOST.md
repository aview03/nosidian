# PC 호스트 동기화 설계 (클라우드 없는 Vault 동기화)

> 상태: 설계 + 선행 보안 작업. v1.38.1 에서 회귀 시험·이 문서, **v1.39.0 에서 Android Keystore 토큰 보호**까지 했다. 쓰기 API·동기화는 아직 구현하지 않았다.
> §14 의 다섯 가지 정책은 사용자가 **확정**했다.
> 목표: PC 를 로컬 동기화 호스트로 써서 Markdown 과 일반 파일을 클라우드 없이 PC·폰이 공유한다. 기존 클라우드(GitHub·Drive·OneDrive)는 그대로 유지한다.

## 0. 원칙

1. **로컬 우선**: 폰에 이미 저장된 Markdown 은 PC 가 꺼져 있어도 계속 읽고 고칠 수 있다. 변경은 보관했다가 다시 연결되면 동기화한다(§9).
2. **새 계층을 만들지 않는다**: 기존 `Provider` 인터페이스(`src/lib/sync/types.ts`)에 "PC 호스트" 구현을 하나 더한다.
3. **Vault 당 동기화 대상은 하나**: 클라우드와 PC 호스트를 한 Vault 에 동시에 켜지 않는다(중복 업로드·충돌 방지).
4. **쓰기는 명시적 허용**: 기본은 읽기 전용. 쓰기는 PC 에서 기기별로 켠다. 삭제는 따로, 초기에는 꺼 둔다.
5. **덮어쓰지 않는다**: 모든 쓰기는 "내가 마지막으로 본 버전(rev)"이 그대로일 때만. 다르면 충돌.
6. AI 승인 구조(변경 제안·파일 제안)는 그대로다 — 승인된 결과가 로컬 저장소에 반영되고, 그 뒤 동기화가 옮긴다.

## 1. 지금 구조 (코드 근거)

| 항목 | 현재 동작 | 호스트 방식에서의 문제 |
| --- | --- | --- |
| Provider | `list / readText / readBase64 / push(changes)`; `push` 는 path → 새 rev 맵 반환 | 조건부 쓰기(내가 본 rev) 입력이 없다 |
| 변경 감지 | 원격 `rev`(GitHub blob sha / Drive md5 / OneDrive cTag)와 로컬 `sha` 비교 (`sync()` in `app.ts`) | 호스트용 rev 를 정의해야 한다(§4) |
| 쓰기 충돌 | GitHub 만 head 가 바뀌면 409/422 → 한 번 다시 받아 합쳐 재시도. Drive·OneDrive 는 무조건 덮어씀 | 호스트는 **항상** 조건부여야 한다 |
| 삭제 | 로컬 삭제 = `deleted` 표시 → push 에서 `content: null`. 원격 삭제 = 목록에서 사라짐으로 추정 | "처음 보는 기기"와 "삭제"를 구분 못 한다 → 삭제 기록(tombstone) 필요 |
| Markdown 충돌 | `mergeNote`(3-way, `base` = 고치기 시작할 때 내용). 겹치면 `conflict` 표시 | 그대로 재사용 |
| 일반 파일 | `assets` 목록(이름·크기·rev)만 동기화, 내용은 눌러서 받기. 올리기·삭제·이동은 `uploadOthers` 등 별도 경로 | 호스트에선 노트와 같은 변경 감지·충돌 규칙을 적용해야 한다 |
| 처음 연결 | 목록 차이를 곧바로 반영 | 양쪽에 데이터가 있으면 위험 → 미리보기(§8) |

## 2. 구성 요소

```
 폰 (IndexedDB = 작업 사본)                PC
 ┌──────────────────────┐   HTTPS+지문     ┌──────────────────────────────────┐
 │ Vault(노트·파일 목록)  │ ◄──────────────► │ 호스트 서비스(fileShare 확장)       │
 │ "내 PC" Provider      │   (기기 ID·토큰) │   └ 호스트 폴더(Vault 저장소, 정본)  │
 └──────────────────────┘                  │ PC 앱 Vault(IndexedDB)             │
                                           │ "로컬 폴더" Provider ◄► 호스트 폴더 │
                                           └──────────────────────────────────┘
```

- **호스트 폴더**: PC 디스크의 일반 폴더. Vault 의 노트(.md)와 일반 파일이 평범한 파일로 들어 있어 탐색기·다른 편집기로도 열린다.
- **PC 앱**도 하나의 클라이언트다: 자기 IndexedDB ⇄ 호스트 폴더를 "로컬 폴더 Provider"(같은 인터페이스, `fs` 사용)로 동기화한다.
- **폰**은 "내 PC" Provider(HTTPS)로 호스트 서비스와 동기화한다. 호스트 폴더가 두 기기의 단일 접점이다.

### 공유 폴더와 호스트 폴더는 다른 기능이다
| | 공유 폴더 (v1.38, 지금) | 호스트 폴더 (설계) |
| --- | --- | --- |
| 목적 | 폰이 PC 의 파일을 **보고 받기** | **Vault 자체**를 동기화 |
| 권한 | 읽기 전용만 | 읽기 + (기기별 허용 시) 쓰기 + (별도 허용 시) 삭제 |
| 폴더 | 아무 폴더 | Nosidian 이 관리하는 Vault 저장소 + `.nosidian/` 메타 |
| 설정 위치 | 노트와 동기화 > 내 PC 폴더 보기 | Vault 의 "보관 위치" 선택지 |
| 겹침 | 호스트 폴더와 **겹치는(같거나 포함하는)** 폴더는 공유 폴더로 지정할 수 없다. 반대도 같다 |

## 3. 권한 모델

| 권한 | 기본 | 범위 | 비고 |
| --- | --- | --- | --- |
| 목록·메타 조회 | 허용 | 페어링된 기기, 호스트 폴더만 | |
| 다운로드 | 허용 | 호스트 폴더 | 기존 `/get` 규칙(경로 우회·링크 차단·해시) |
| 생성·수정 | **기기별로 PC 에서 허용** | 지정한 Vault(호스트 폴더) 하나 | 켠 뒤엔 매번 확인하지 않는다. PC 에서 언제든 끈다(즉시) |
| 삭제 | **별도 권한, 초기 비활성** | 〃 | 호스트는 물리 삭제하지 않고 휴지통(§6)+tombstone |
| Vault 밖 경로 | 항상 차단 | — | |
| 파일 실행 | 항상 차단 | 전체 | 호스트는 어떤 파일도 열거나 **자동 실행하지 않는다**. 모바일 → PC 의 실행 파일 쓰기는 거부한다(§3.1) |

### 3.1 실행 파일 정책 (확정)
- **모바일 → PC 호스트 쓰기: 거부.** PC 에서 사용자가 직접 폴더에 넣은 실행 파일은 막지 않는다(호스트는 열거나 실행하지 않는다). PC → 모바일 전송은 현재 정책(폰은 실행 파일을 받지 않음, v1.34)을 유지한다.
- 차단 확장자: `.exe .dll .sys .msi .msp .bat .cmd .com .scr .pif .ps1 .psm1 .vbs .vbe .wsf .wsh .hta .cpl .msc .reg .lnk .jar .apk`.
- **확장자만 믿지 않는다**: 파일 머리의 실행 파일 표지(PE `MZ`, ELF `\x7fELF`, Mach-O)가 보이면 확장자와 무관하게 거부한다. 다만 이것은 **보조 방어**이고 완전하지 않다 — 진짜 방어선은 "호스트는 어떤 파일도 자동 실행하지 않는다"이다.
- 기본값은 항상 차단이다. 나중에 실행 파일 동기화를 명시적으로 허용하는 옵션을 만들더라도 **기본은 차단**을 유지한다.

- 권한은 **기기별**(기기 ID 에 붙음)이고, 올리는 쪽(폰)은 스스로 올릴 수 없다 — 권한 변경은 PC UI 에서만.
- 권한이 해제되면 진행 중이던 쓰기는 다음 요청에서 403. 폰은 읽기 전용으로 내려가며 로컬 변경은 보관된다(§9).

## 4. 버전(rev) 설계

해시만으로는 "삭제 후 같은 내용으로 다시 만든 파일"이나 "A→B→A 로 되돌린 파일"을 구분하지 못한다.

- `rev = "<gen>.<hash16>"` — `gen` 은 **경로별 단조 증가 카운터**, `hash16` 은 내용 SHA-256 앞 16자.
- 내용이 바뀔 때, **삭제될 때, 삭제 후 다시 만들어질 때** 마다 `gen` 이 +1. 그래서 같은 해시라도 rev 가 다르다.
- 호스트 폴더의 `.nosidian/manifest.json` 이 경로 → `{gen, hash, size, mtime, by}` 와 삭제 기록 `{path, gen, deletedAt, by}` 를 가진다.
- `.nosidian/` 은 목록·공유 대상에서 제외(숨김). 탐색기에서 보이므로 "수정하지 마세요" 안내 파일을 둔다.
- 클라이언트의 `NoteFile.sha`(마지막으로 받은/올린 rev)가 그대로 "내가 본 rev"가 된다 — 새 필드가 필요 없다.

## 5. 조건부 쓰기 프로토콜 (구현은 다음 단계)

```
POST /sync/put    { path, baseRev|null, b64 }  → 200 { rev } | 409 { currentRev, deleted? } | 403 | 413
POST /sync/delete { path, baseRev }            → 200 { rev(tombstone) } | 409 | 403(삭제 권한 없음)
```
- `baseRev == null`: 새로 만들기 — 현재 파일도 tombstone 도 없어야 한다(tombstone 위에 만들려면 그 rev 를 baseRev 로).
- 서버는 현재 rev 가 `baseRev` 와 같을 때만 반영한다. 다르면 **아무것도 쓰지 않고** 409 + 현재 rev.
- **원자적 저장**: ① `.nosidian/tmp/<uuid>` 에 쓰고 fsync → ② `.nosidian/journal` 에 의도 기록 → ③ 대상 위치로 `rename` → ④ manifest 갱신(임시+rename) → ⑤ journal 삭제. 시작할 때 journal 을 확인해 ③ 이 끝났으면 ④ 를 이어서(롤포워드), 아니면 tmp 를 버린다.
- **경로 규칙**(기존 `cleanRel` 재사용 + 쓰기용 추가): 상대 경로만, `..`·숨김·`:`·역슬래시·예약 이름 거절 / 부모 디렉터리의 `realpath` 가 호스트 폴더 안이어야 함 / 대상이 링크면 거절 / 대소문자만 다른 경로 충돌 거절 / 폴더는 서버가 만든다(링크가 아닌 일반 폴더만).
- **크기 제한**: 파일 25MB(기존 상한), 요청 본문은 base64 포함 한도, 호스트 폴더 총량·요청 속도 제한(디스크 고갈 방지).
- **단일 작성자**: manifest 는 호스트 프로세스만 쓴다. `.nosidian/host.lock` 으로 이중 실행을 막는다.

## 6. 삭제

- 호스트는 파일을 물리적으로 지우지 않고 `.nosidian/trash/<gen>-<이름>` 으로 옮기고 tombstone 을 남긴다.
- tombstone 은 다른 기기가 다음 동기화에서 "삭제됨"을 받게 한다. 이로써 "처음 보는 기기"와 "삭제"를 구분한다.

### 6.1 휴지통과 tombstone 의 보관 (확정, 둘은 별개다)
| | 내용 | 기본 보관 | 정리 조건 |
| --- | --- | --- | --- |
| 휴지통(`.nosidian/trash`) | 지운 파일의 **내용**(복구용) | 90일 | 기간이 지나면 정리 |
| tombstone(manifest) | 삭제됐다는 **기록**(전파용) | 90일 이상 | **90일 경과 AND 등록된 모든 기기가 그 삭제를 확인(ack)** 했을 때만 |

- manifest 는 기기마다 `ackGen`(그 기기가 반영을 마친 가장 높은 번호)을 둔다. 삭제 기록의 `gen` 이 모든 활성 기기의 `ackGen` 이하이고 90일이 지났을 때만 tombstone 을 지운다. **90일이 지났다는 이유만으로 지우지 않는다** — 그러면 100일 만에 켜진 폰에 남아 있던 파일이 PC 로 되살아날 수 있다.
- 내용(휴지통)이 먼저 사라져도 tombstone 은 남을 수 있다(기록이 내용보다 오래 간다).
- PC 에서 **기기를 해제하면** 그 기기의 ack 는 기다리지 않는다(승인 기록 정리). 해제 안 한 채 오래 접속하지 않은 기기(기본 **180일**)는 "장기 미접속"으로 표시하고, 다시 연결할 때 **최초 연결과 같은 전체 비교·미리보기·사용자 확인**을 거친다(자동 동기화하지 않는다).
- **삭제 vs 수정 충돌**: 한쪽이 삭제, 다른 쪽이 수정했으면 **수정을 살린다**(삭제 취소, 데이터 보존 우선)하고 알린다.
- 초기 단계에서는 삭제 권한이 꺼져 있다 — 폰에서 지운 파일은 호스트에 전파되지 않고 폰에만 남는다는 안내가 필요하다.

## 7. 충돌 정책

| 대상 | 규칙 |
| --- | --- |
| Markdown(.md) | 기존 `mergeNote`(3-way, `base`)를 그대로 쓴다. 겹치지 않으면 자동 병합, 겹치면 지금처럼 `conflict` 표시로 사용자가 고른다 |
| 바이너리·기타(.docx·.zip·.exe …) | **자동 병합·덮어쓰기 금지**. 409 가 나면 사용자에게 선택지를 준다: ① 내 것을 새 이름으로 보관 ② PC 것을 유지 ③ 내 것으로 덮어쓰기(= 최신 rev 를 baseRev 로 명시해 다시 올림). 기본 선택 없음 — **v1.43.5 구현**(`docs/HOST-PHONE.md` "바이너리 충돌 선택") |
| 삭제 vs 수정 | §6 — 수정 유지 |
| 같은 경로 동시 생성 | 둘 다 `baseRev=null` → 나중 것이 409. 내용 해시가 같으면 충돌 아님(동일 취급) |

## 8. 최초 연결: 미리보기 후 확인

양쪽에 이미 데이터가 있으면 **자동으로 합치지 않는다.** 연결 직전에 읽기만 하는 계획(plan)을 만든다.

분류(양쪽 목록·rev·해시 비교):
1. PC 에만 있음 → 폰으로 받을 항목
2. 폰에만 있음 → PC 로 올릴 항목(쓰기 권한 필요)
3. 같은 경로·같은 내용(해시 동일) → 할 일 없음
4. 같은 경로·다른 내용 → **사용자가 항목별 선택**(기본 선택 없음; .md 는 병합 시도 결과도 미리보기)
5. tombstone 이 있는 경로 → 별도 표시

원칙: 계획 단계에서는 **쓰기 0건** · 최초 연결에는 **삭제 전파 없음**(삭제 예정 항목 기본 0) · 확인 전에는 반영하지 않고 · 취소하면 아무 것도 바뀌지 않는다.

### 8.1 최초 연결 전 스냅샷 (확정: 기본 필수)
- 반영을 시작하기 **전에** 양쪽의 현재 상태를 복구할 수 있게 남긴다:
  - **PC**: 호스트 폴더(와 PC 앱 Vault 의 목록·rev)를 `.nosidian/snapshots/<시각>/` 에 보관한다(파일 내용은 같은 볼륨이면 하드링크·복사).
  - **폰**: Vault 의 노트·파일 목록을 앱 안(IndexedDB 의 별도 저장소)에 복원 가능한 형태로 보관한다.
- **스냅샷을 만들지 못하면 최초 동기화를 시작하지 않는다.** 저장 공간이 부족하면(필요 용량 추정 > 여유 공간) 시작 전에 알리고 중단한다.
- 보관: 최근 3개 또는 30일(둘 중 먼저). 사용자가 설정에서 바꾸거나 지울 수 있다.

## 9. 오프라인 우선 · PC 가 꺼져 있을 때

- 폰의 IndexedDB 가 항상 작업 사본이다. 읽기·수정은 PC 연결과 무관하게 된다.
- 변경은 기존 `dirty`/`deleted` 표시로 보관된다(재시작해도 유지). 새 저장 계층이 필요 없다.
- 동기화는 연결될 때 **pull → 병합 → push** (지금과 같은 순서). PC 가 안 보이면 조용히 건너뛴다(알림은 사용자가 직접 동기화를 눌렀을 때만).
- 동기화 실패는 **파일 단위로 원자적**이다: 실패한 파일은 dirty 로 남고, 성공한 파일만 rev 가 갱신된다. 실패가 로컬 데이터를 바꾸지 않는다.

## 10. PC 쪽 일관성 (IndexedDB ⇄ 호스트 폴더)

- **외부 변경 감지**: PC 앱 시작 시, 동기화 직전, (선택) 폴더 감시에서 디스크를 스캔한다. 크기+mtime 으로 후보를 거르고 해시로 확정 → 달라진 파일은 `gen`+1 (`by: external`), 사라진 파일은 tombstone, 새 파일은 추가.
- **두 곳이 모두 바뀐 경우**: PC 앱의 IndexedDB 변경(dirty)과 탐색기 변경이 같은 파일이면 §7 규칙(.md 는 3-way, 그 밖은 사용자 선택).
- **비정상 종료**: 쓰기 도중이면 journal 로 복구(§5). IndexedDB 만 앞서 있으면 다음 시작 때 동기화가 따라가고, 디스크만 앞서 있으면 시작 스캔이 반영한다.
- **탐색기에서의 이름 바꾸기·이동**은 "삭제 + 새 파일"로 보인다. 같은 해시면 이동으로 추정해 사용자에게 알려 준다(자동 처리하지 않는다).

## 11. 주소·기기 식별

- **기기 식별 = 기기 ID(페어링 시 발급) + 인증서 지문.** IP 는 힌트일 뿐 식별자가 아니다. IP 가 바뀌어도 새 기기가 아니다.
- 연결 시도 순서: 마지막으로 성공한 주소 → 저장된 주소 후보 → (실패 시) "PC 의 새 주소 입력" 안내(PC 카드에 현재 주소 표시). 연결에 성공하면 서버가 **현재 주소 목록**을 알려 주고 폰이 갱신한다.
- 입력한 주소로 갔는데 **지문이 다르면 자동으로 재연결하지 않는다**(이미 구현된 동작) — 연결 해제 후 QR 로 다시.
- mDNS 같은 자동 탐색은 폰 웹뷰에서 쓸 수 없어 이번 설계에 넣지 않는다.
- PC 의 인증서가 유지돼야 하므로 v1.38.1 에서 회귀 시험을 추가했다(`fileShare.cert.test.ts`).

## 12. 위협 모델: 쓰기가 들어오면 달라지는 점

| 데이터 손실(충돌·잘못된 덮어쓰기) | 조건부 쓰기, 휴지통, 최초 연결 미리보기, 삭제 기본 비활성 |
