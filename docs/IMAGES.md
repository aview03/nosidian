# 이미지 넣기 (붙여넣기·끌어놓기·이미지 버튼)

> 배경: 페르소나 점검 F20(`docs/personas/FINDINGS.md`) — 앱에서 이미지를 **넣을 방법이 없었다**. 저장소에 있는 이미지를 받아 보기만 했다. 사용자가 (a) "편집기에서 넣고 동기화로 올리기"를 선택(2026-11-11).
> 상태: **구현 완료(1~3단계), PC 앱 확인(붙여넣기→본문 링크→읽기 화면 렌더)**. 미확인: 폰(갤러리/카메라 선택), 끌어놓기·이미지 버튼 실사용, 실제 저장소(GitHub 등) 업로드, 큰 사진 줄이기(캔버스)의 실기기 동작. 시험: `images.test.ts` 15개 + `sync.test.ts` 3개.

## 목표
1. 편집기에서 **붙여넣기(Ctrl+V)·끌어놓기·툴바의 `이미지` 버튼**(모바일은 갤러리/카메라 선택)으로 이미지를 넣는다. 넣는 즉시 `![](…)` 가 본문에 들어가고 읽기 화면에 보인다.
2. **저장소가 없어도** 쓸 수 있다(이 기기에만 저장). 저장소를 연결하면 **다음 동기화 때 올라간다**(노트와 같은 "대기 중" 개념).
3. 오프라인·실패해도 이미지를 잃지 않는다. 다른 기기에서도 같은 상대 경로로 보인다.
4. 기존 동기화·"파일 올리기"·AI 정책(승인 없이는 AI 가 쓰지 못함)은 건드리지 않는다.

## 결정 (사용자가 따로 정하지 않아 정한 기본값 — 바꾸고 싶으면 알려 주세요)
| 항목 | 정한 것 | 이유 |
| --- | --- | --- |
| 저장 위치 | **그 노트와 같은 폴더의 `_assets/`** (예: `프로젝트/시험/_assets/이미지-20261111-101500.png`) | 노트를 폴더째 옮겨도 링크가 안 깨지는 상대 경로, 폴더가 다른 노트끼리 섞이지 않음 |
| 링크 모양 | `![이름](_assets/파일.png)` (노트 기준 상대 경로) | 기존 `resolveAsset` 이 이미 상대 경로를 푼다 |
| 파일 이름 | 붙여넣기: `이미지-YYYYMMDD-HHMMSS.확장자`, 끌어놓기·선택: 원래 이름(금지 문자만 `_`). **같은 이름이 있으면 ` (2)`** (`uploadPath` 재사용) | 클립보드 이미지는 이름이 없거나 전부 `image.png` |
| 허용 형식 | png · jpg/jpeg · gif · webp · bmp · avif (**svg 제외**) | svg 는 스크립트를 담을 수 있어 처음엔 뺀다(이미지로만 그려져 실행되진 않지만 보수적으로) |
| 크기 | **원본 25MB 이하**(기존 파일 올리기와 같은 상한). 사진은 **긴 변 2048px 초과 또는 3MB 초과면 줄여서(JPEG 0.85) 저장**, gif·webp 애니메이션·투명 png 는 그대로 | 폰 사진(4~12MB)이 저장소를 불리지 않게. 줄였으면 그 사실을 알림 |
| 삭제 | 이번 범위 밖: 노트에서 링크를 지워도 이미지 파일은 남는다(고아). 기존 "파일 > 삭제"로 지울 수 있다 | 정책이 필요(다른 노트가 같은 이미지를 쓸 수 있음) |
| AI | 이 기능과 무관. AI 는 이미지를 만들지 않는다 | 기존 정책 유지 |

## 데이터 모델 (기존 구조를 최대한 재사용)
- 이미지 메타는 기존 `assets[path] = { sha, id?, size? }`, 바이트는 IndexedDB `assets` 레코드의 `b64`·`mime`(이미 `loadAsset` 이 읽는 곳).
- **새로 추가: `pending?: true`** — 아직 저장소에 올리지 못한 이미지(`sha: null`). 메모리(`assets[path].pending`)와 IndexedDB 레코드 양쪽에 둔다.
- 동기화(`sync()`)가 달라지는 곳:
  1. **받기**: 원격 목록으로 `assets` 를 다시 만들 때 **`pending` 항목은 남긴다**(안 그러면 "원격에서 사라진 이미지"로 보고 지워 버린다). 원격에 같은 경로가 이미 있으면 원격 것이 우선하고 대기 항목은 버린다.
  2. **올리기**: 노트 push 앞에서 `pending` 이미지를 `PushChange.b64` 로 올리고(기존 `uploadOthers` 와 같은 방식), 성공하면 `pending` 을 지우고 `sha` 를 채운다. 실패하면 대기 상태로 남는다(오프라인).
  3. **연결(`connect`)**: 로컬 사본을 원격 기준으로 바꿀 때 대기 이미지는 **지우지 않고 유지**한다(새 노트 `dirty && !sha` 를 유지하는 것과 같다).
- 저장소가 없으면 `pending` 이 영영 남지만 문제 없다(저장소를 연결하면 그때 올라간다). 호스트("내 PC")·클라우드 모두 같은 `Provider.push` 를 쓴다.

## 화면
- **편집기**: `paste`(클립보드에 이미지 파일이 있으면 가로채 처리, 글 붙여넣기는 그대로)·`drop`(이미지 파일만) 처리, 툴바 `이미지` 버튼(파일 선택, `accept="image/*" multiple` — 안드로이드 WebView 는 갤러리/카메라를 고르게 한다). 커서 위치에 `![이름](경로)` 삽입(여러 장이면 줄마다).
- 처리 중에는 "이미지를 넣는 중…" 알림, 끝나면 "이미지 N장을 넣었어요 (저장소에는 다음 동기화 때 올라가요)"(저장소가 없으면 "이 기기에만 저장돼요"). 줄였으면 "큰 사진은 줄여서 저장했어요".
- 읽기 화면은 기존 `Reader` 가 `loadAsset`(IndexedDB 의 b64)으로 그대로 보여 준다.
- 허용하지 않는 형식·큰 파일은 이유를 알리고 그 파일만 건너뛴다.

## 단계
| 단계 | 내용 |
| --- | --- |
| 1 | 순수 함수(`lib/images.ts`): 형식·크기 판정, 이름 만들기, 경로, 마크다운 조각, 줄일지 판단 + 시험 |
| 2 | 저장·동기화(`app.ts`): `attachImages()`, `pending` 올리기·보존·연결 시 유지 + 시험(가짜 원격) |
| 3 | 편집기: 붙여넣기·끌어놓기·`이미지` 버튼 + 알림 |
| 4 | 실제 확인: PC 앱(붙여넣기·읽기 화면), 폰(갤러리 선택) |

## 알려진 한계(미리 적어 둠)
- 노트를 지워도 이미지는 남는다(고아 정리 없음). 같은 이미지를 여러 노트에 쓰면 중복 저장된다.
- 이미지 이름 바꾸기·이동 시 본문 링크를 자동으로 고치지 않는다(기존 `moveOther` 와 같다).
- svg·동영상·PDF 는 이 경로로 넣지 못한다(PDF 등은 기존 "파일 올리기").
