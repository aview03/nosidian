# 프로젝트 깊이와 용어 (v1.43.7, 첫 걸음)

> 같은 앱에서 **요구 수준이 크게 다른 사람**(예: 시안 일정만 적는 디자이너 ↔ PRD·정책서·결정 기록·WBS 를 쓰는 기획자)을 함께 다루는 방법.
> 한 줄 원칙: **깊이는 사람(역할)이 아니라 프로젝트가 정한다.** 엔진(업무·노트·꼬리표)은 하나이고, 무거운 문서류는 엔진을 늘리지 않고 **템플릿 + 규칙**으로 얹는다.
> 역할(페르소나)은 처음 켤 **기본값**(홈 타일, 새 프로젝트의 기본 템플릿)에만 쓴다 — 기능의 유무를 바꾸지 않는다(`docs/UX-PERSONAS.md`).

## 구성 (이번에 만든 것)
| 무엇 | 어떻게 | 어디서 읽나 |
| --- | --- | --- |
| **깊이** `depth: light` | 프로젝트 개요 노트의 속성. **가볍게**이면 허브에서 `문서`·`문서 점검` 탭을 숨긴다. 속성이 없으면 표준(모든 탭 — 기존 프로젝트는 그대로) | `lib/projectKind.ts` `depthOf` · `ProjectHub.tsx` |
| **용어** `words: design` | 상태 이름을 그 일의 말로: `할 일→시작 전`, `진행 중→시안 중`, `대기→검토 요청`, `완료→확정`(보드 열). **내부 값(`status`·`side`)은 그대로** — 이름만 번역한다 | `wordsOf` · 허브 그룹 제목·업무 줄 배지·보드 열·업무 편집기 칩 |
| **템플릿 `디자인 일정`** | 개요(`depth: light` · `words: design`) + 일정 업무 4줄(`start:`~`due:`, 담당자 포함). 문서 틀 없음 | `projectTemplates.ts` |
| **템플릿 `기획 정식`** | 개요 + `PRD`·`정책서`·`기능설계서`·`IA 구조도`·`결정 기록`(결정 안건 `kind:decision`)·`회의록` 틀 + 간트에 막대로 보이는 일정 업무 6줄 | 〃 |
| **전환** | 허브 `⋯` 메뉴: `가볍게 보기 (문서·점검 숨김)` ↔ `문서·점검 탭 보이기`. 개요 노트의 `depth` 한 줄만 바꾼다 — **데이터는 그대로**(무손실) | `setFmKey` |
| **기본 선택** | 새 프로젝트 마법사: 디자이너 → `디자인 일정`, 기획자 → `기획 정식`, 그 밖 → `일반`(바꿀 수 있다) | `defaultTemplateId` |

직접 적어도 된다: 개요 노트 맨 위에 `depth: light`(또는 `가볍게`·`simple`·`간단히`), `words: design`(또는 `디자인`).

## 왜 이렇게
- 같은 사람도 가벼운 프로젝트와 무거운 프로젝트를 함께 한다(기획자도 사소한 건 한 줄). 역할로 깊이를 고정하면 둘 다 불편하다.
- 헤비 문서는 새 기능이 아니라 **노트**다: PRD·정책서 = 문서 틀 + 문서 점검(필수 섹션), 결정 기록(ARD) = 결정 안건, WBS = 간트 보기. 이미 있는 부품을 템플릿이 묶는다.
- 용어 번역: 내부 모델(`status:waiting side:other`)을 그대로 보여 주지 않고 사용자의 말로 보여 준다. 저장되는 값이 같아서 다른 사람이 같은 프로젝트를 표준 용어로 봐도 서로 호환된다.

## 함께 고친 것
- **템플릿의 `start:` 꼬리표**: 마감일을 정하지 않으면 `start:{{due-N}}` 가 `start:NaN-NaN-NaN` 이 됐고, 프로젝트를 템플릿으로 저장하면 `start:` 가 절대 날짜로 남았다. 이제 둘 다 `due:` 처럼 처리한다(빠지거나 `{{due±N}}` 로).
- 새 템플릿은 모든 업무 줄에 담당자를 넣어, 만들자마자 `담당자 없는 일`로 **`주의` 배지가 뜨던 것**을 피했다. (기존 `행사`·`콘텐츠` 템플릿에도 같은 현상이 있을 것으로 보이나 이번에 확인하지 않았다.)

## 한계·다음 걸음
- **검토 받은 날짜의 자동 기록은 없다**: `검토 요청` 상태는 있지만, 검토가 끝난 날을 자동으로 남기지는 않는다(상태가 바뀐 날을 기록하는 기능은 확인하지 못했다). 필요하면 상태 전환 시 날짜 꼬리표(예: `reviewed:`)를 남기는 것이 다음 후보.
- **WBS 의 계층(하위 업무)**: 지원하는지 확인하지 않았다. 간트는 시작~마감 막대만 안다.
- **홈 타일·허브 탭의 더 큰 정리**(홈 기본 타일 수, `문서 점검` 탭의 1차 노출 여부)는 아직 하지 않았다 — 사람이 쓰는 모습을 관찰한 뒤 정한다(`docs/personas/` 의 점검은 사람 관찰이 아니다).
- 템플릿이 늘면 유지 비용이 커진다: 기본 제공은 5개(일반·행사·콘텐츠·디자인 일정·기획 정식), 그 밖은 사용자가 프로젝트를 템플릿으로 저장해 쓴다(`Templates/`).
- 폰 실기기에서의 확인은 하지 못했다(이번 점검 때 폰이 USB 에서 분리돼 있었다). PC 앱(시험 인스턴스)과 컴포넌트 시험으로 확인했다.
