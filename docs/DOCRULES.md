# 문서 규칙 · 문서 점검 · AI 쓰기 정책

프로젝트 문서의 **역할**(개요·정책·할 일 …)과 지켜야 할 구조를 사람이 읽는 노트로 정하고, 문서가 그 구조에 맞는지 **점검**한다. AI 를 연결하지 않아도 쓰는 기능이고, 나중에 AI(MCP·LLM)가 문서를 쓸 때 같은 규칙을 읽어 통제하는 기반이다.

> 방향: "AI 가 쓰는 Markdown, 사람이 관리할 수 있도록." 규칙을 AI 에게 알려 주는 것과 규칙을 시스템이 강제하는 것을 분리한다 — 이 규칙 파일은 앱이 직접 해석한다.

## 원칙
- **일반 Markdown**: 규칙도 노트(`_workspace/문서규칙.md`). 전용 DB·형식 없음. 팀이 같이 쓰고 노트와 함께 동기화·3자 병합된다.
- **기본은 꺼짐**: 파일이 없거나 `rules: off` 면 앱은 지금과 똑같다. 프로젝트 밖 노트는 어떤 경우에도 점검하지 않는다.
- **알려 주기만**: 사람이 편집한 문서도, 동기화로 들어온 문서도 저장을 막거나 자동으로 고치지 않는다. 점검 결과는 저장하지 않고 매번 계산한다.
- **규칙 파일은 AI 가 고칠 수 없다**(`isProtectedPath`: `_workspace/` 전체): 자기 행동을 제한하는 규칙을 스스로 풀지 못하게. 규칙은 사람이 일반 편집기로 바꾼다.

## 규칙 파일: `_workspace/문서규칙.md`
```md
---
rules: on              # off(기본)·파일 없음 = 아무것도 점검하지 않음
apply: opt-in          # opt-in(기본): 프로젝트 노트에 docs: 가 있는 프로젝트만 | all-projects
ai_write: propose      # read | propose(기본) | direct  — 앞으로의 AI 쓰기용(지금은 읽기만)
ai_new_file: approve   # approve(기본) | template-only | deny
---
## 프로필: 기본
- 개요  :: file=프로젝트 개요.md; official; entry; singleton
- 할 일 :: file=할 일.md; official; singleton
- 회의록 :: file=회의록.md; official
- 보조  :: dir=보조/; aux

## 상태
draft, review, final, archived

## 무시
- 보조/a.md <> 보조/b.md      # 중복 후보에서 뺄 쌍
```
- 줄 하나 = 역할 하나: `이름 :: key=값; key=값; 플래그` (`보기.md` 와 같은 형식). 모르는 키·플래그는 무시한다(앞으로 늘어도 이전 버전이 깨지지 않게). 해석하지 못한 줄은 줄 번호와 함께 점검 화면에 알린다.
- 처음 만들면(점검 탭의 "문서 규칙 켜고 이 프로젝트에 적용") 앱의 프로젝트 템플릿이 만드는 파일 이름(`프로젝트 개요.md`·`할 일.md`·`회의록.md`, 영어 UI 면 `Project Overview.md` …)에 맞춘 기본 프로필과 설명이 들어간다. 개발 프로젝트용 예시(README/SPEC/DECISIONS)는 "예시" 섹션에 적용되지 않는 형태로 들어 있다.

| 키·플래그 | 뜻 |
|---|---|
| `file=` | 프로젝트 폴더 기준 상대 경로. 이 이름·위치의 문서가 이 역할(대소문자 무시) |
| `dir=` | 이 폴더 아래의 문서가 이 역할(보조용) |
| `official` / `aux` | 공식 문서 / 보조 문서 |
| `singleton` | 프로젝트에 하나만 |
| `entry` | 진입 문서: 여기서 링크를 따라 닿을 수 있어야 하는 출발점(프로젝트 노트는 항상 진입 문서) |
| `must` | 이 문서가 꼭 있어야 함(없으면 "빠진 문서" 안내). 기본은 아님 |
| `required=제목,제목` | 필수 제목(공백·대소문자 무시, 아래가 비어 있어도 누락으로 침) |
| `append-only` | 해석만 한다. 점검하지 않음 |

## 적용 범위
- 점검 단위는 **프로젝트 폴더**. 프로젝트 노트(`type: project`)의 속성 `docs: 기본` 이 그 프로필을 고른다(`docs: on` = `기본`, `docs: off` = 끔). `apply: all-projects` 면 `docs:` 가 없는 프로젝트에도 `기본` 을 적용하고 `docs: off` 만 뺀다.
- 프로젝트 폴더 밖 노트, `Templates/`, `_보관/` 안은 점검하지 않는다. `status: archived` 문서는 점검에서 빠진다.

## 공식 문서 / 보조 문서 판정
1. 노트 속성 `role:` 이 없으면 **이름**으로: `file=` 과 같은 상대 경로 → 그 역할, 아니면 `dir=` 아래 → 그 역할(가장 깊은 폴더), 아니면 **미분류**(오류 아님).
2. `role:` 이 있으면 이름 규칙과 맞춰 본다. **무조건 우선하지 않는다.**
   - 프로필에 없는 이름 → `unknownRole`
   - 이름 규칙이 가리키는 역할과 다름(README.md 에 `role: 정책`) → `roleConflict`
   - 공식 역할인데 정해진 자리(`file=`)가 아니거나 보조 폴더 안 → `roleMisplaced`
   - 위 셋은 **역할을 확정하지 않는다**(공식 문서로 인정되지 않음). 그래서 AI 가 `role:` 로 공식 문서를 사칭하거나 규칙을 우회할 수 없다.
3. 공식 역할 문서에만 필수 제목·status 검사를 한다(보조 문서는 안 함). 프로젝트 노트의 `status:` 는 프로젝트 상태(active 등)라서 문서 status 검사에서 뺀다.

## 점검 판정 (모두 표시만 함, 막지 않음)
| 종류 | 기준 | 수준 |
|---|---|---|
| 역할 충돌·위치 불일치·모르는 역할 | 위 2번 | 확인 |
| 하나뿐이어야 하는 역할이 둘 이상 | `singleton` 역할로 인정된 문서가 2개 이상 | 확인 |
| 빠진 문서 | `must` 역할의 `file=` 문서가 없음 | 참고 |
| 필수 제목 누락 / 비어 있음 | 공식 문서에 `required=` 제목이 없거나, 제목은 있는데 다음 같은/상위 제목 전까지 글자가 없음 | 확인 |
| status | 허용 값(`## 상태`)이 아님 → 확인, 공식 문서에 없음 → 참고 | |
| 끊어진 링크 | 가리키는 노트가 없음(코드 안은 제외) → 확인 / 노트는 있는데 `#제목` 이 없음 → 참고 | |
| 고아 | 다른 어떤 노트에서도 링크되지 않음(공식 문서·진입 문서·보관 제외) | 참고 |
| 개요에서 접근 불가 | 링크는 받지만 진입 문서에서 링크를 따라 닿을 수 없음(공식 문서는 링크가 없어도 여기서 잡음). **고아와 겹치지 않게 나눈다** | 참고 |
| 중복 후보 | **같은 폴더** 안 두 문서가 아래 신호 중 **둘 이상**: ① 이름에서 `v2·final·최종·복사본·숫자` 꼬리를 뗀 뿌리가 같음 ② 제목 구성 겹침 ≥ 70%(제목 2개 이상) ③ 본문 단어 5개 조각 유사도 ≥ 0.6(각 200자 이상). `## 무시` 쌍·같은 `singleton` 역할 쌍(따로 표시)은 제외 | 참고 |

- 중복은 단정하지 않고 "후보 + 근거"만 보인다. **의미가 같고 글자가 다른 중복은 LLM 없이는 못 찾는다.**
- 비용: 이름 뿌리·제목으로 먼저 거르고, 그 후보에만 본문 유사도를 계산한다(전체 쌍 비교 안 함). 기준값(`DUP`)은 초기 실험값 — 실제 노트로 돌려 보며 조정한다.

## AI 쓰기 정책 엔진 (`lib/docpolicy.ts`)
AI 가 Nosidian 의 도구로 문서를 쓰려 할 때 부를 **순수 함수** `checkAiWrite(요청, 규칙, 프로젝트들, 파일들)`. 파일을 고치지 않고 판정만 돌려준다. **아직 어떤 AI 에도 연결되어 있지 않다**(MCP·LLM 은 다음 단계). 사람이 직접 하는 편집·동기화에는 쓰지 않는다.

- **판정 셋**: `allow`(바로 반영, 삭제는 `effect: archive` = 지우지 않고 `_보관/` 으로) · `require_approval`(승인 대기 — **허가가 아니다**) · `deny`(거절). 이유(`reason`)와 값(`text`)을 함께 준다.
- **모든 쓰기**: `create` · `modify` · `delete` · `move`(이름 바꾸기 포함). `move` 는 출발지·도착지를 모두 검사한다.
- **검사 순서** (앞이 이긴다)
  1. **보호 경로**(`_workspace/` 전체, 규칙 파일 포함) — 규칙 on/off·다른 정책과 관계없이 거절. 이동의 도착지가 보호 경로여도 거절(우회 방지).
  2. **규칙이 없거나 꺼져 있음** → 자동 쓰기 불가(`require_approval`/`noRules`). 규칙을 적용하지 않는 프로젝트·프로젝트 밖(`outside`), 프로필을 못 읽음(`noProfile`)도 같다. *"AI 의 자동 쓰기는 규칙이 허용한 곳에서만."*
  3. **`ai_write: read`** → 전부 거절(`ai_new_file` 과 무관).
  4. **버전 검사** — `baseHash`(AI 가 읽은 시점의 `contentHash`)가 없으면 `noBase`, 지금과 다르면 `stale` 로 거절. 없는 문서 수정은 `missing`, 이미 있는 자리에 만들기·옮기기는 `exists`.
  5. 종류별:
     | 행위 | 공식 문서 | 보조·미분류 문서 |
     |---|---|---|
     | 수정 | `propose` → 승인 대기 / `direct` → 허용 | 허용 |
     | 삭제 | 거절(`officialDelete`) | 허용 + 보관(`archive`) |
     | 이동·이름 바꾸기 | 거절(`officialMove`) | 같은 프로젝트 안이면 허용. 도착지가 공식 역할 자리면 새 공식 문서와 같게(`propose` → 승인 대기, 하나뿐인 역할이 이미 있으면 거절). 다른 프로젝트·범위 밖으로는 승인 대기(`leavesProject`) |
     | 생성 | `ai_new_file`: `deny` 거절 · `approve` 승인 대기 · `template-only` 프로필에 등록된 파일 이름만(공식이고 `propose` 면 승인 대기). 하나뿐인 역할이 이미 있으면 거절 | (위와 같음) |
  - `role:` 로 공식 문서를 사칭한 문서는 역할이 정해지지 않으므로(위 "역할 판정") 공식으로 취급하지 않는다 — 그래서 승인 경로를 우회하지도, 이름으로 공식 역할을 빼앗지도 못한다.
- **승인과 실행 분리**: `resolveForApply(요청, 승인했나, …)` 가 **반영 직전에** 판정을 처음부터 다시 한다. 승인 대기 중에 사람이 문서를 고쳤거나(`stale`) 규칙이 바뀌었으면 승인했어도 거절하고, `deny` 는 승인으로 뒤집히지 않는다.
- 한계: Nosidian 을 거치지 않고 원본 파일을 직접 쓰는 에이전트는 이 엔진으로 통제할 수 없다(MCP 자체는 샌드박스가 아니다).

## 변경 제안 검토·승인
정책 엔진이 `require_approval` 로 돌린 쓰기를 사람이 검토하고 반영하는 흐름이다.
- **제출**: AI 도구가 `proposalStore.submit(요청, 제안자, 설명)` 을 부른다 → `triage`(= 정책 판정 + 반영 계획) 결과가 `allow` 면 바로 반영, `require_approval` 이면 **제안으로 보관**, `deny` 면 아무것도 하지 않는다. (아직 부르는 AI 도구가 없다 — 개발 중에는 localStorage `nosidian.dev=1` 로 콘솔의 `window.__proposals` 에서 직접 넣어 본다.)
- **보관**: vault 노트가 아니라 **기기(localStorage, vault 별)** 에 둔다 — 아직 승인되지 않은 임시 값이고 팀 동기화 대상이 아니다. 처리된 제안은 최근 20건만 남긴다.
- **검토 화면**: 내 업무 위쪽에 "AI 의 변경 제안 N건이 승인을 기다려요 · 검토" 줄이 생기고, 누르면 제안마다 종류·경로·제안자·이유와 **전후 차이**(바뀐 줄 ±2줄, 새 문서는 전체)를 보여 준다. 이동은 `출발 → 도착`, 삭제는 "보관함으로 옮겨요". 읽은 뒤 문서가 바뀌었으면 승인 버튼이 꺼진다.
- **승인 = 재검증 요청**: 승인하면 `resolveForApply` 로 판정을 **처음부터 다시** 한다. 통과하면 계획(`FileOp`: create·set·rename·delete)대로 쓰고 `applied`, 그새 문서가 바뀌었거나(`stale`) 규칙이 막으면(`readOnly` 등) 반영하지 않고 `failed` + 이유를 남긴다. 거절은 `rejected`.
- 삭제는 실제로 지우지 않고 `_보관/<원래 경로>` 로 옮긴다(이미 있으면 ` (2)` 번호).

## Human View (프로젝트 허브 "문서" 탭)
규칙을 적용한 프로젝트의 문서 탭은 파일 목록 대신 **무엇을 먼저 읽어야 하는가**로 보여 준다: ① 열린 일·결정할 일·"문서 점검" 링크(확인할 것 N), ② **먼저 읽어야 할 문서** — 프로젝트 노트와 공식 역할 문서를 프로필의 역할 순서대로(역할 이름·status·확인 N), ③ **보조·기타 문서**(접힘). 보관(`archived`) 문서는 목록에서 빠진다. 규칙을 적용하지 않은 프로젝트는 지금까지의 단순 목록이다. **AI 와 무관**: 마크다운과 규칙 노트에서 매번 계산하고 저장하지 않는다.
