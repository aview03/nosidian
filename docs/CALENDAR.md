# 일정 관리 · 위젯

메모/뷰어 위에 얹은 일정 기능. **일정은 별도 DB 없이 마크다운 노트에서 읽어 온다.**
그래서 기존 동기화(GitHub / Google Drive / OneDrive), 충돌 처리, 오프라인이 그대로 적용된다.

## 1. 일정 쓰는 법

| 형태 | 예 | 비고 |
|---|---|---|
| Daily 노트의 체크리스트 줄 | `- [ ] 14:00-15:00 치과` | 파일명이 `YYYY-MM-DD.md`인 노트(위치 무관). 시간은 생략하면 종일 |
| 다른 노트의 체크리스트 + `@날짜` | `- [ ] 보고서 제출 @2026-11-20` | 어느 노트에나 쓸 수 있음 |
| 프론트매터 `date` | `date: 2026-11-12` | `end`(기간), `time`, `title`, `color`, `repeat`, `until` 지원 |

반복: 체크리스트 줄 끝에 `repeat:weekly until:2026-12-31`, 또는 프론트매터의 `repeat:`/`until:`.
값은 `daily weekly monthly yearly weekdays` 또는 `매일 매주 매월 매년 평일`.
요일을 골라 반복하려면 `repeat:weekly:mon,wed,fri` (sun mon tue wed thu fri sat).

며칠에 걸친 일정: 줄에 `end:2026-11-25`를 붙인다. 예) `- [ ] 부산 출장 end:2026-11-12`.
시작일부터 종료일까지 매일 보이고 둘째 날부터는 "계속"으로 표시된다. (기간과 반복은 함께 쓸 수 없다.)
펼쳐진 반복은 오늘부터 2년 뒤까지 보이고(최대 900건), 없는 날짜(31일 등)는 건너뛴다. 완료 체크는 원본 줄에서만 된다.

날짜 색상: Daily 노트 프론트매터의 `color: "#d01010"`. 화면에서는 날짜 머리글의 색 버튼으로 고른다.

### 비어 버린 Daily 노트는 자동 정리
일정을 모두 지우거나(편집기 삭제, 날짜 메모창에서 글을 모두 지움, 일정을 다른 날로 옮김, 날짜 색을 지움) 그날 Daily 노트에 **템플릿 뼈대(`# 날짜`, `## 할 일`, `## 메모`, 빈 체크박스)만 남으면 노트 파일도 함께 삭제**한다(동기화하면 원격에서도 삭제, 알림 문구 없이 조용히). 메모 글, 일정, 사용자가 만든 소제목, 날짜 색 프론트매터가 하나라도 있으면 지우지 않는다(`isSkeleton`/`pruneDaily`, lib/calendar.ts). **이미 쌓여 있던 빈 노트**는 새 버전을 처음 실행할 때 vault 마다 **한 번 자동으로 일괄 정리**한다(`pruneAllDaily`, localStorage `nosidian.pruned.<vaultId>` 로 중복 실행 방지, 지운 개수는 알림으로 알림). 이후 동기화로 들어온 빈 노트는 명령 팔레트의 "빈 Daily 노트 정리" 또는 설정 > 캘린더 > "지금 정리"로 정리한다. 판별 규칙이 같아서 메모·일정·소제목·날짜 색이 있는 노트와 날짜가 아닌 이름의 노트는 지우지 않는다.

### 일정 편집기 (GUI)
문법을 몰라도 쓸 수 있도록 폼으로 입력한다. 결과는 위의 마크다운 한 줄로 저장된다.

- 열기: 입력창 옆 **상세** 버튼(새 일정), 또는 목록의 **일정을 눌러** 수정.
- 항목: 제목 · 날짜 · 며칠에 걸친 일정(종료일) · 종일/**시작·종료 시각**(기기 시간 선택기, 30분·1시간·1.5시간·2시간·3시간 길이 버튼) · 반복(안 함/매일/평일/매주/매월/매년, 매주는 **요일 칩**으로 복수 선택) · 반복 종료일.
- 맨 아래 한 문장 요약("11월 9일 (월) · 19:00–20:30 · 매주 월, 수, 금")으로 저장될 내용을 바로 확인. 잘못된 조합(종료가 시작보다 빠름 등)은 이유를 보여 주고 저장을 막는다.
- 수정: 날짜를 바꾸면 그 날의 Daily 노트로 줄이 옮겨진다. 반복 일정은 시리즈 전체를 수정/삭제한다. 삭제는 확인 창을 거친다.
- 프론트매터 `date` 노트 일정은 편집기 대신 노트가 열린다.

### 빠른 입력 (자연어)
입력창에 쓰면 날짜·시간·반복이 풀려서 Daily 노트에 한 줄로 들어간다.

| 입력 | 결과 |
|---|---|
| `내일 3시 치과` | 내일 15:00 치과 (오전/오후 표시가 없고 1~6시면 오후로 처리) |
| `금요일 19:00-20:30 저녁` | 이번 주 가장 가까운 금요일 |
| `다음주 수요일 회의` | 다음 주 수요일 |
| `11월 20일 보고서`, `12/25 파티`, `2026-12-25` | 해당 날짜 |
| `매주 금요일 7시 스터디` | 반복 포함 |

시간 앞의 `오전/오후/아침/저녁/밤`, `3시 30분`, `3시 반`도 인식한다. 해당 날의 Daily 노트가 없으면 만들어서 넣는다.

## 2. 화면

- **시작 화면**: PC·모바일 모두 **내 업무**(`homeTab()`, 안드로이드 뒤로가기도 여기로 먼저 돌아간 뒤 종료). 자세히는 [WORK.md](WORK.md).
- **PC**: 레일 = 내 업무 / 캘린더 / 메모 / 검색. 캘린더는 월간·주간·목록 + 오른쪽 "선택한 날" 패널(일정, 빠른 입력, 그날 Daily 노트 편집기). 왼쪽 사이드바는 다가오는 일정. 날짜 칸 더블클릭 = 입력창 포커스.
- **모바일**: 하단 탭 = 내 업무 / 캘린더 / 메모 / 검색 / 설정. "내 업무"는 오늘 일정 + 업무 대기열 + 프로젝트. (위젯 창의 "오늘" 보기는 따로 오늘 일정 + 지난 14일 미완료 + 향후 7일.) 캘린더는 **월간**(격자 + 선택한 날 목록) / **주간**(7일을 세로로) / **목록**(그 달 전체)이 실제로 다른 화면으로 바뀐다.
- **그래프**는 보조 기능: 노트 우측 패널의 "로컬 그래프 → 크게 보기"와 명령 팔레트("그래프 보기")에서만 연다.
- 명령 팔레트(`Ctrl+P`): "캘린더 열기", "오늘 일정 보기".
- 공휴일·음력은 설정 > 캘린더에서 끌 수 있다. 음력은 1일·15일에만 작게 표시.

공휴일: 외부 데이터 없이 `Intl`(중국력)로 계산한다(설날·추석·부처님오신날 + 고정 공휴일 + 대체공휴일 일반 규칙).
**임시공휴일·선거일은 포함하지 않는다.** 2025·2026년은 실제 달력과 대조했다.

## 3. 알림

설정 > 캘린더 > 일정 알림: 끔 / 5 / 10 / 30분 전 (시간 있는 일정만, 완료한 일정 제외).

| 플랫폼 | 방식 |
|---|---|
| PC | 앱 또는 위젯 창이 열려 있는 동안 `Notification`. 본 창과 위젯이 둘 다 떠 있어도 Web Locks로 한 창만 담당. 창을 모두 닫으면 울리지 않음 |
| Android | AlarmManager(`setAndAllowWhileIdle`)에 앞으로 8일치 최대 60건 등록 → 앱이 꺼져 있어도 울림. 정확 알람 권한을 요구하지 않으므로 절전 모드에서는 몇 분 늦을 수 있음. 재부팅 시 저장된 목록으로 재등록. 알림을 누르면 앱의 그 날로 이동 |

## 4. PC 위젯 (Electron)

설정 > 바탕화면 위젯. 보기(월간/오늘/목록), 위치(바탕화면/항상 위), 투명도(항상 위일 때만), 로그인 시 위젯만 시작.

**보기와 조작 (월간이 기본, DesktopCal 방식)**
- 월간 보기는 화면을 크게 채우는(기본 크기: 바탕화면 아이콘 줄만 남기고 거의 전체) 반투명 달력이다. 배경화면이 비치고, 칸마다 날짜·공휴일(빨강)·그날의 일정 글자가 전부 보인다. 칸이 모자라면 `+n`. 머리글의 "화면에 크게 펼치기" 버튼으로 언제든 다시 크게 만든다.
- **칸을 누르면 그 옆에 날짜 메모창(포스트잇)**이 열린다. 한 줄에 일정 하나를 글로 적고 ✓(또는 Ctrl+Enter, 바깥 클릭)로 확정한다. `14:00 치과`, `19:00-21:00 저녁`, `내일 3시 약속`처럼 쓰면 시간·날짜가 풀려서 그 날(또는 다른 날) Daily 노트의 일정 줄로 저장된다. 완료한 일은 줄 앞에 `✓`. 반복·기간·다른 노트의 일정은 메모창 아래에 따로 나오고 눌러서 편집기로 연다. 팔레트로 날짜 색, "시간·반복 설정"으로 일정 편집기, "노트 열기".
- 칸 안의 일정 글자를 누르면 일정 편집기가 위젯 안에서 열린다(수정·삭제). `saveDayText`/`dayText`(lib/calendar.ts)가 메모창의 글 ↔ 노트 줄 변환을 맡는다.
- 설정 > 바탕화면 위젯 > "배경 진하기"로 배경화면 위에 얹는 어두운 정도를 조절한다.

**투명해 보이게 하는 방법**: 바탕화면에 붙인 창은 진짜 투명이 안 되므로(아래), 로컬 서버(`/__wallpaper`)가 현재 바탕화면 파일(`%APPDATA%\Microsoft\Windows\Themes\TranscodedWallpaper`)을 내려주고, 위젯이 그것을 창 위치(`window.screenX/Y`)에 맞춰 그린 뒤 어두운 막을 얹는다.
- **배경 위치는 추측하지 않고 측정한다** (`electron/wallpaperFit.cjs`). Windows 의 "채우기"는 이미지 비율에 따라 가운데가 아닌 위치에서 자르기도 한다(이 PC: 16:10 이미지를 16:9 화면에 → 위에서 1/3 지점, 가운데 정렬 대비 20px 어긋남을 실측으로 확인). 그래서 위젯을 켠 뒤 2.5초 뒤(그리고 배경화면 파일이 바뀌거나 모니터 구성이 바뀔 때) 위젯을 잠깐 숨기고 `desktopCapturer`로 화면을 캡처해 원본 이미지와 겹쳐 보며 "차이가 작은 픽셀 비율"이 가장 큰 위치·배율을 찾는다(1차 축소본에서 대략, 2차 원본 크기에서 ±6px 정밀 보정). 다른 창이 일부 가려도 동작하고, 점수가 0.35 미만이면 측정 실패로 보고 가운데 정렬(`cover`)로 대체한다. 측정 후 위젯 배경과 실제 바탕화면의 평균 픽셀 차이 14.0 → 0.08, 위치 오차 0px 로 검증.
- `Progman` 은 `PrintWindow` 로 캡처할 수 없고(`ok=False`) 24H2 에는 별도의 배경 창(WorkerW)도 없어서, 화면 캡처 + 이미지 매칭 방식을 택했다.
- 한계: "채우기"와 같은 비율 확대(`cover`)를 가정한다(맞춤/바둑판/스팬 설정이면 측정 실패 → 가운데 정렬). 모니터마다 다른 배경화면·슬라이드쇼는 위젯이 놓인 모니터 기준으로 한 장만 쓴다. 바탕화면이 바뀌면 최대 약 30초 뒤 다시 측정한다. 측정하는 순간 위젯이 0.3초쯤 깜빡인다.

**글 쓰는 창은 별도의 일반 창 (한글 입력 때문)**
- 바탕화면(Progman)에 붙인 위젯 창은 영문 키 입력은 받지만 **한글 입력기(IME)는 동작하지 않는다**(한글 모드에서 `gksrmf` 입력 시 입력창이 비어 있음을 실제 키 입력으로 재현). 바탕화면의 자식 창은 "활성 창"이 아니어서 TSF/IME 가 연결되지 않기 때문이다. 코드로 값을 넣는 시험으로는 이 문제가 보이지 않는다 — **입력 관련 시험은 반드시 실제 키보드(SendKeys)·한글 모드로 할 것**.
- 그래서 위젯 안에서는 글을 쓰지 않는다. 칸을 누르면 `widget:popup` IPC 로 메인이 **작은 최상위 창**(프레임 없음, 항상 위, 작업표시줄 제외)을 칸 옆에 띄우고(`/?widget=1&popup=note&date=…`), 일정 글자를 누르면 같은 방식으로 일정 편집기 창(`popup=editor&ev=…`)을 띄운다. `PopupApp`(components/Widget.tsx)이 이를 그린다. 위젯의 "오늘/목록" 보기의 입력창도 "일정 추가" 버튼으로 바뀌어 같은 창을 연다.
- 메모창은 **포커스를 잃으면(바깥을 누르면) 저장하고 닫힌다**. 창을 닫기 직전에 `flushPersist()` 로 400ms 디바운스 저장을 즉시 IndexedDB 에 써서 내용이 유실되지 않게 하고, `BroadcastChannel` 로 위젯 칸이 바로 갱신된다.

**이동·크기 조절 (끌 때 끊기지 않게)**
- 머리글을 끌면 이동, **네 변·네 모서리**를 끌면 가로/세로를 각각 조절한다(최소 280×300).
- 끄는 동안에는 위젯 화면을 **흐리게 고정**하고 아무것도 다시 계산하지 않는다(내용 크기 고정, 배경 보정·줄 수 계산 중단). 끝났을 때 한 번만 다시 그린다. 크기 조절 중에는 가운데에 "1482 × 825"처럼 크기를 표시한다.
- 이동량은 렌더러의 마우스 좌표가 아니라 **메인 프로세스가 `screen.getCursorScreenPoint()` 로 16ms 마다 직접 읽는다**(`widget:drag-start`/`drag-end`). 창이 움직이면 렌더러의 `screenX` 가 흔들려 이동량이 몇 배로 튀는 문제가 있었다. 버튼을 뗐는지는 `GetAsyncKeyState`(koffi)로 확인해 창 밖에서 떼도 끝난다.

**구조**
- 위젯은 같은 origin(`http://localhost:47321/?widget=1`)의 별도 `BrowserWindow`. 그래서 본 창과 **같은 IndexedDB**를 쓴다.
- 창 사이 변경은 `BroadcastChannel('nosidian-db')`로 알리고 받은 쪽이 DB에서 다시 읽는다(`reloadFromDb`). 이 창이 아직 저장하지 않은 편집(디바운스 중)은 덮어쓰지 않는다.
- 동기화는 본 창만 한다(`initLocal`은 vault를 읽기만 함). 설정(`localStorage`)이 바뀌면 위젯이 스스로 새로고침해 테마·언어·vault를 따라간다.
- 위젯에서 일정을 누르면 IPC(`widget:open-note`)로 본 창을 앞으로 띄우거나 새로 만들어 그 노트를 연다.
- 위젯이 떠 있는 동안은 본 창을 닫아도 앱이 유지된다. 트레이 아이콘에서 앱 열기 / 위젯 끄기 / 종료.
- 상태(위치·크기·모드·레이어·자동 시작)는 `userData/widget.json`에 저장. 저장된 위치가 연결된 모니터 밖이면 기본 위치로 복귀.

**바탕화면에 붙이는 방식** (`electron/desktopLayer.cjs`, `koffi`로 user32 호출)
- 위젯 창을 **Progman(바탕화면 창)의 자식**으로 `SetParent`하고 `HWND_TOP`으로 올린다 → 아이콘 목록 위, 일반 창 아래. Win+D에도 남고 클릭을 받는다.
- 자식이 되면서 남는 제목줄·두꺼운 테두리 스타일을 제거해야 가장자리에 띠가 안 생긴다.
- 5초마다 붙어 있는지 확인해 탐색기 재시작 시 다시 붙인다.
- Win11 24H2에서 검증했다. 이전 버전은 같은 원리지만 확인하지 않았다. 실패하면 일반 창으로 대체되고 설정 화면에 안내가 나온다.

**시도했다가 버린 방식 (재시도하지 말 것)**
- 아이콘 *뒤*(WorkerW)에 붙이기: 마우스 입력을 받지 못한다.
- 최상위 창을 `HWND_BOTTOM`으로 내리기: Win+D 때 바탕화면 창에 가려진다.
- 자식 창에서 투명 배경 / `setOpacity`: 투명 부분이 검게 나오거나 내용이 검은 상자로 나온다. **그래서 바탕화면 레이어의 위젯은 불투명 카드**이고, 투명도는 "항상 위" 모드에서만 동작한다.

**패키징**: `koffi`와 `@koromix/koffi-win32-x64`를 `build.files`에 포함하고 `asarUnpack`으로 `.node`를 푼다(설치 파일에서 동작 확인). 자동 시작은 `app.setLoginItemSettings({ args: ['--widget-only'] })`.

## 5. Android 위젯 · 알림

설정 > 홈 화면 위젯의 버튼으로 런처에 위젯 추가를 요청한다(런처가 확인 창을 띄움).

**데이터 흐름**
```
노트 변경 → startNativeBridge(src/lib/nativeCal.ts)
  └ buildPayload(): 스냅샷(지난 35일~앞으로 120일의 일정, 공휴일 날짜) + 알림 목록
      └ CalendarBridge.setSnapshot() → SharedPreferences("nosidian_cal")
          ├ 위젯 갱신 (MonthWidgetProvider / AgendaWidgetProvider)
          └ AlarmManager 재등록 (Reminders)
```
변경 후 1.2초 뒤, 앱이 백그라운드로 갈 때는 즉시 보낸다. **위젯은 앱이 넘겨준 데이터만 보여 주므로, 클라우드 동기화로 들어온 일정은 앱을 한 번 열어야 위젯에 반영된다.**

**위젯**
- 월간: 6주 격자, 오늘 강조, 일요일·공휴일 빨강. 헤더는 `‹ 연월 ›` + 오른쪽 `오늘`(`+` 없음). 격자 셀은 `RemoteViews` TextView 42개(`cell_0..41`).
  - 칸 안: 날짜 + 일정 제목 칩(공휴일 이름이 맨 앞, 빨강). 위젯 크기(`getAppWidgetOptions`)에서 칸 너비·높이를 어림해 보일 줄 수와 글자 수를 정하고, 줄이 모자라면 `(줄-1)`개 + `+N`(최소 1개 + `+N`). 제목은 한글 1·영문 0.55 폭으로 어림해 `…` 로 줄인다. 크기를 바꾸면 `onAppWidgetOptionsChanged` 로 다시 그린다. 공휴일 이름은 스냅샷의 `holn`.
  - **주의**: RemoteViews 는 `View` 같은 허용 목록 밖의 뷰를 쓰면 위젯 전체가 "위젯을 추가할 수 없습니다"로 뜬다(빈 간격은 `TextView` 로). 앱 캘린더 헤더도 같은 순서(`‹ 연월 ›`, `오늘`).
- 일정 목록: `RemoteViewsService`(ListView), 오늘부터 30일, 날짜 머리글 + 일정.
- 눌렀을 때: 딥링크 `com.amsidian.app://calendar?date=YYYY-MM-DD[&add=1]` → 앱이 캘린더 탭으로 그 날을 선택(`add=1`이면 입력창 포커스). 위젯 안에서 직접 편집은 하지 않는다("조회 + 눌러서 열기").
- 날짜가 바뀌는 것은 `updatePeriodMillis`(30분)에 의존한다.

**네이티브 파일** (`android/app/src/main/java/com/amsidian/app/`)
`CalendarBridgePlugin`(웹↔네이티브, 알림 권한, 위젯 추가 요청) · `CalStore`(스냅샷 보관/파싱) · `MonthWidgetProvider` · `AgendaWidgetProvider`(+`AgendaService`) · `Reminders`(알람 등록, 수신, 부팅 재등록) · `Links`(딥링크). 리소스는 `w_*` 접두사(`values/w_strings.xml`은 영어, `values-ko`는 한국어).

## 6. 빌드 · 검증

```
npm run dev                       # 브라우저
npm run desktop                   # PC(Electron) 개발 실행
npm run dist                      # PC 설치 파일 (release/)
npm run build && npx cap sync android
set JAVA_HOME=C:\Program Files\Android\Android Studio\jbr   # JDK 21 + jlink 필요
cd android && gradlew.bat assembleDebug
```
- IntelliJ 내장 JBR은 `jlink`가 없어서 Android 빌드에 쓸 수 없다. 시스템 JDK 17은 Capacitor 8(자바 21)과 맞지 않는다.
- PC 위젯을 실제 프로필을 건드리지 않고 시험하려면 `electron electron/main.cjs --user-data-dir=<빈 폴더> --remote-debugging-port=9333`, `<빈 폴더>/widget.json`에 `{"enabled":true}`를 미리 써 둔다.
- Android WebView는 디버그 빌드에서 `adb forward tcp:9444 localabstract:webview_devtools_remote_<pid>`로 DevTools(CDP)에 붙을 수 있다.

## 8. 알려진 한계 · 후속 과제

- 바탕화면 위젯은 불투명(위 4장 참고).
- 임시공휴일·선거일 미반영. 기간+반복을 함께 쓴 노트는 첫 날짜만 반복된다.
- 번역은 영어까지만 추가(그 외 언어는 영어로 대체 표시).
- Android: 위젯 선택 화면의 미리보기 이미지 없음, 릴리스 빌드·서명 미검증, 재부팅 후 알람 재등록은 코드만 있고 시험하지 않음, 위젯 안 직접 편집 없음.
- PC: 마우스로 끄는 이동·크기 조절은 IPC 경로만 검증했고(포인터 이벤트는 직접 확인 필요), 로그인 자동 시작은 레지스트리를 건드려 시험하지 않았다.
