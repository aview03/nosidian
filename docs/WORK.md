# 프로젝트·업무 (내 업무)

노트 앱 위에 얹은 **소규모 팀용 프로젝트 관리**. 핵심은 두 가지다.

1. **데이터는 노트(마크다운)에만 있다.** 프로젝트·업무·결정·대기열·건강도·타임라인·보기 결과는 모두 노트에서 매번 계산한 **파생 값**이고, 따로 저장하지 않는다(`src/lib/work.ts` 외). 앱을 지워도 `.md` 는 사람이 읽을 수 있는 형태로 남는다.
2. **비개발자는 GUI로, 개발자는 텍스트로.** 모든 기능은 폼(편집기·마법사)으로 쓸 수 있고, 결과는 체크리스트 한 줄의 꼬리표(`due:2026-11-12 owner:민수`)다. 손으로 써도 같은 결과가 된다.

계획·배경·결정 기록은 [phase2/02-구현-계획.md](phase2/02-구현-계획.md). 일정·위젯 규격은 [CALENDAR.md](CALENDAR.md).

## 1. 쓰는 법 (문법)

### 프로젝트
노트 맨 위(프론트매터)에 `type: project` 를 넣으면 그 노트가 프로젝트다.

```yaml
---
type: project
status: 진행 중
owner: 민수
due: 2026-12-20
health: warning     # 사람이 판단한 상태(시스템이 계산하는 점검과 별개로 표시)
title: 행사 준비     # 없으면 첫 번째 # 제목, 그것도 없으면 파일 이름
---
```

### 업무 한 줄
체크리스트(`- [ ]` / `- [x]`) 한 줄에 `key:value` 꼬리표를 붙인다. **체크박스는 표준 마크다운만 쓴다** — 다른 마크다운 도구에서도 그냥 체크박스 + 글자로 읽힌다.

```
- [ ] 장소 예약금 입금 due:2026-11-06 owner:민수 p:1
- [ ] 룸 가능 여부 문의 status:waiting side:other due:2026-11-08
- [ ] 현수막 시안 정하기 status:doing owner:지현
- [ ] 장소를 식당으로 할지 집으로 할지 kind:decision due:2026-11-12 owner:민수
- [x] 날짜 확정 kind:decision owner:민수 => 토요일 저녁으로 결정
```

| 꼬리표 | 값 | 뜻 |
|---|---|---|
| `due:` | `YYYY-MM-DD` | 마감일. **날짜가 따로 없는 업무는 이 날짜에 캘린더 일정으로도 나타난다**. 결정 안건에서는 "다시 확인할 날" |
| `start:` | `YYYY-MM-DD` | 시작일(선택). 프로젝트 허브 **간트**에서 `start:`~`due:` 가 막대가 된다. 마감만 있으면 마름모 한 점, 둘 다 없으면 "날짜가 없는 일". 캘린더 일정에는 영향이 없다(`due:` 만 쓴다). 편집기에서는 `시작일`(마감보다 늦으면 저장 불가) |
| `owner:` | 이름, 여러 명은 `owner:"홍길동, 김철수"` | 담당자 |
| `p:` | `1`~`3` | 우선순위(1이 가장 높음, 화면에 `!`) |
| `status:` | `doing`(진행 중) · `waiting`(대기) · `dropped`(취소됨) · 한글 `진행중` `대기` `취소됨`도 가능(예전 이름 `접음`도 읽음) | 상태. 없으면 "할 일". 완료는 체크박스(`[x]`) |
| `side:` | `me` · `other`(한글 `나` `상대`) | 공이 누구에게 있나. `other` 면 대기로 본다 |
| `kind:` | `decision`(한글 `결정` `미결` `안건`) | 결정이 필요한 안건. 닫을 때 결론 필수([8장](#8-결정미결-닫을-때-결론-필수)) |
| `proj:` | `proj:[[프로젝트 이름]]` | 소속 프로젝트를 줄 단위로 지정 |
| `impact:` | 한 줄 | 과업·비용에 미치는 영향 |
| `=> 결론` | 줄 끝까지 | 협의/결정을 닫을 때의 결론 |

기존 일정 꼬리표(`@날짜`, `end:`, `repeat:`, `until:`, 앞의 `14:00`)와 함께 쓸 수 있다. 일정 쪽은 업무 꼬리표를 제목에서 걷어 낸다. 모르는 `status:` / `side:` / `kind:` 값은 지우지 않고 글자 그대로 둔다.

### 내 이름 (팀)
설정 > 업무 > **내 이름**(쉼표로 여러 개/별명). `owner:` 가 내 이름을 포함하는 업무만 "내 것"으로 모은다. **담당자가 없는 일은 누구에게나 보인다**(배정해야 하므로). 이름이 비어 있으면 전체를 보여 준다.

## 2. 무엇이 업무인가

노트 안의 모든 체크리스트가 업무는 아니다(장보기 목록이 업무 대기열을 채우면 안 된다). 다음 중 하나여야 한다.
1. 업무 꼬리표가 하나라도 있다, 또는
2. 어떤 프로젝트에 속해 있다, 또는
3. 루트의 **`받은 업무.md`**(영어 `Inbox.md`)에 있다 — 마감·담당 없이 적은 것도 "정리할 업무"에 보이게 하는 예외([7장](#7-받은-업무-정리)).

**프로젝트 소속**(우선순위 순): ① 줄의 `proj:` / 노트 프론트매터 `project: [[이름]]` → ② 프로젝트 노트가 있는 **폴더 아래**(가장 깊은 폴더가 이김) → ③ 프로젝트 노트 자신. 코드 블록 안의 체크리스트는 무시한다.

## 3. 내 업무 화면

앱의 **시작 화면**(PC·모바일 모두, 모바일 탭 "내 업무", PC 레일 첫 번째). 화면은 **타일**들이 세로로 쌓인 모음이고, 사용자가 순서·표시를 고른다([11장](#11-사용자-정의-타일)). 맨 위에는 "내 것 / 전체" 전환(설정의 "내 이름"이 있을 때)이 있다.

- **기본 타일 10개** — 각 줄 오른쪽에 *왜 여기 있는지*(`기한 3일 지남`, `D-3`, `대기 · 기한 1일 지남`, `다시 확인 2일 지남` …)를 한 열로 보여 준다. 구분선 없이 간격으로만 묶는다.

  | 타일 | 들어오는 것 | 처음 상태 |
  |---|---|---|
  | 오늘 일정 | 오늘의 일정(빠른 입력 포함, 모바일은 입력줄이 화면 아래). 업무 대기열에 이미 있는 항목은 중복해서 보이지 않는다 | 보임 |
  | 기한이 지난 일 | `due` 가 지난 열린 일(대기·결정 제외) | 보임 |
  | 결정할 일 | 열린 결정 안건(다시 확인일 기준) | 보임 |
  | 오늘 마감 | `due` 가 오늘 | 보임 |
  | 이번 주 | `due` 가 7일 이내 | 숨김 |
  | 대기 중인 일 | `status:waiting` 또는 `side:other` — **내 기한 초과와 섞지 않는다** | 보임 |
  | 진행 중 | `status:doing` | 숨김 |
  | 담당자 없는 일 | 마감일이 있거나 프로젝트에 속한 일 중 담당자 없음 | 숨김 |
  | 정리할 업무 | 어느 프로젝트에도 속하지 않은 일([7장](#7-받은-업무-정리)) | 보임(비면 화면에서 빠짐) |
  | 프로젝트 | 상태·마감·열린 일 수·시스템 점검 문구, "+ 새 프로젝트" | 보임 |

- 비어 있는 타일은 평소 화면에서 빠진다(오늘 일정·프로젝트·사용자 타일 제외). 타일 제목을 누르면 접히고, 줄이 많으면 처음 몇 줄만 보이고 "N개 더 보기"로 펼친다.

규칙: 완료(`[x]`)·취소됨(`dropped`)은 어디에도 나오지 않는다. 체크하면 원본 노트의 `[x]` 가 바뀌고(결정 안건은 예외, 8장), 줄을 누르면 업무 편집기가 열린다(원본 노트는 줄 오른쪽 아이콘).

## 4. 업무 편집기 (GUI)

꼬리표를 몰라도 쓸 수 있도록 폼으로 입력한다. 결과는 위 문법의 한 줄로 노트에 저장된다.

- **열기**: 내 업무·프로젝트 허브의 업무 줄을 누르면 수정, 상단 **+**(업무 추가)로 새 업무.
- **항목**: 제목 · 상태(할 일/진행 중/대기/취소됨) · 결정이 필요한 안건 · 완료 · 결론(완료·취소됨일 때) · 마감일(오늘/내일/일주일 뒤 버튼) · 담당자(지금까지 쓰인 이름 제안, "나" 버튼) · 우선순위(높음/보통/낮음) · 프로젝트(앱 전용 선택 상자).
- **대기** = `status:waiting side:other` 두 꼬리표를 함께 쓴다(상대 차례).
- **수정은 그 줄만** 바꾼다: 들여쓰기·불릿, 일정 꼬리표(시간·`@날짜`·`end:`·`repeat:`·`until:`), 모르는 `status:`/`side:`/`kind:` 값을 보존(`rewriteTaskLine`). 그새 노트 위에 줄이 생겨 줄 번호가 밀려도 같은 제목으로 줄을 찾고(`findTaskLine`), 못 찾으면 아무것도 쓰지 않고 알린다.
- **새 업무의 위치**: 프로젝트를 고르면 그 폴더의 "할 일" 노트 끝에(없으면 새로 만듦, 프로젝트 노트가 폴더 밖이면 그 노트 끝에), 프로젝트가 없으면 **"받은 업무" 노트**에 모은다. 폴더로 이미 소속되므로 `proj:` 꼬리표는 쓰지 않고, **기존 업무의 프로젝트를 바꿀 때만** `proj:[[이름]]` 을 쓴다(줄을 옮기는 건 7장).
- 삭제는 확인 창을 거친다. 노트 이름(할 일·받은 업무)은 UI 언어를 따른다.

## 5. 프로젝트 허브

내 업무의 프로젝트 목록을 누르면 열린다(레일/탭은 "내 업무"가 활성). 머리글에 프로젝트 이름(title > 첫 # 제목 > 파일 이름), 상태·담당·마감, 사람이 입력한 **판단**(`health`), 시스템 **점검**, 열린 일 수, **+** 업무 추가, 노트로 열기. 탭은 **할 일 · 보드 · 문서 · 타임라인**(글자만 있는 밑줄 탭).

- **할 일**: 결정할 일 · 진행 중 · 할 일 · 대기로 나누고(각 마감일순), 완료·취소됨은 접어 둔다(결론은 줄에 `→ 결론`).
- **보드**(칸반): 할 일 · 진행 중 · 대기 · 완료 네 칸. 카드를 끌어 놓거나 카드 오른쪽 ‹ › 로 옮기면 그 줄의 `status`(대기는 `side:other` 포함)·완료 체크만 바뀐다(`moveTask`). 취소됨은 보드에 나오지 않는다. PC는 칸 폭 고정, 모바일은 칸을 옆으로 넘겨 본다(끌기보다 ‹ › 버튼).
- **문서**: 프로젝트 폴더 아래의 노트(프로젝트 노트가 폴더 밖이면 안내).
- **타임라인**: [10장](#10-타임라인).

## 6. 새 프로젝트 마법사 · 템플릿

내 업무의 "+ 새 프로젝트"(또는 명령 팔레트 "새 프로젝트")에서 템플릿을 고르고 이름·마감일·담당자를 넣으면 `프로젝트/<이름>/` 폴더에 문서가 만들어지고 허브가 열린다.

- **템플릿 3종**: 일반(개요+할 일) · 행사(마감일에서 거꾸로 잡힌 준비 일정 7개 + 회의록) · 콘텐츠(기획→제작→검수→배포 6단계). 결과는 평범한 노트라서 만든 뒤 자유롭게 고친다.
- **자리표시자**: `{{name}}` `{{owner}}` `{{due}}` `{{today}}` `{{due-14}}`(마감일 14일 전). 마감일·담당자를 비우면 그 꼬리표는 줄에서 빠진다. 같은 이름의 폴더가 있으면 ` (2)` 를 붙인다.
- 구현: `src/lib/projectTemplates.ts`(순수 함수) + `src/lib/templatePaths.ts` + `src/components/NewProject.tsx`.

### 내 템플릿 (vault 의 `Templates/`)
내장 3종 외에 **사용자가 만든 템플릿**이 같은 목록에 "내 템플릿" 표시와 함께 나온다.
- **만드는 법 ① (GUI, 권장)**: 프로젝트 허브 머리글의 **템플릿으로 저장**. 이 프로젝트의 문서·할 일이 `Templates/<이름>/` 로 복사되며 틀로 바뀐다 — 프로젝트 이름은 `{{name}}`, 프로젝트 노트의 `owner:` `due:` `title:` 은 자리표시자, 할 일의 완료 표시·`=> 결론`·`status:`/`side:` 는 지우고, 마감일은 **프로젝트 마감 기준 `{{due-N}}`/`{{due+N}}`**(프로젝트 마감이 없으면 뺌), 프로젝트 담당자 이름은 `{{owner}}`. 같은 이름이 있으면 ` (2)`.
- **만드는 법 ② (손으로)**: vault 루트의 `Templates/`(또는 `템플릿/`) 아래에 폴더를 만들고 노트를 넣는다. 폴더 하나가 템플릿 하나이고 폴더 이름이 템플릿 이름이다. 노트 안과 **파일 이름**에 자리표시자를 쓸 수 있다(`{{name}} 회의록.md`). 프로젝트 노트의 머리말에 `template: 한 줄 설명` 을 적으면 목록에 설명으로 나오고(새 프로젝트에는 복사되지 않음), 없으면 "내 템플릿 · 문서 N개".
- 프로젝트 노트(`type: project`)가 없는 폴더도 템플릿이 된다(개요 노트를 자동으로 만들어 넣음).
- **`Templates/` 안의 노트는 진짜 프로젝트·업무로 세지 않는다**(내 업무·허브에 나타나지 않음). 팀 vault 에 두면 팀원 모두 같은 템플릿을 쓴다.

## 7. 받은 업무 정리

프로젝트 없이 적어 둔 업무(주로 루트의 `받은 업무.md`)는 내 업무에 **정리할 업무** 섹션으로 모인다(프로젝트가 하나라도 있을 때). 업무 편집기에서 프로젝트 없이 추가한 업무가 여기로 간다. `받은 업무.md` 의 체크리스트 줄은 꼬리표가 없어도 전부 업무로 센다. 다른 노트의 평범한 체크리스트는 업무가 아니다.

줄의 **"프로젝트로 옮기기…"** 에서 프로젝트를 고르면 그 프로젝트의 "할 일" 노트로 **줄이 옮겨 간다**(마감·담당·우선순위·상태·결정 표시는 그대로, 원래 노트에서는 지워짐 — `moveToProject`).

## 8. 결정·미결 (닫을 때 결론 필수)

회의에서 "정해야 하는 일"은 할 일과 달리 **결론을 내야 끝난다.** 같은 체크리스트 줄에 `kind:decision` 을 붙여 안건으로 만든다.

- `due:` 는 **다시 확인할 날**, `side:other` 는 상대의 답을 기다리는 안건. 열린 안건은 프로젝트를 가로질러 내 업무의 **결정할 일**에 따로 선다(다른 대기열과 겹치지 않음. "다시 확인 N일 지남"/"오늘 다시 확인"/"D-N"). 프로젝트 허브에서는 "결정할 일"이 맨 위 묶음이다.
- **닫기 = 결론 한 줄 필수.** 체크박스를 누르면 바로 체크되지 않고 편집기가 "결정함"으로 열리며, 결론이 비면 저장이 잠긴다. 다른 화면(캘린더 등)에서 체크해도 결론(`=> …`)이 없으면 거절하고 안내한다(`toggleTask` 가드).
- 편집기의 "결정이 필요한 안건" 체크로 켜고 끈다. 상태 변경·프로젝트 이동·수정해도 `kind` 는 유지된다.
- 아직 회의록 노트 안의 `[decision]` 같은 별도 문법은 없다(체크리스트 한 줄 하나로 통일).

## 9. 프로젝트 건강도 (시스템 점검)

내 업무의 프로젝트 줄과 허브 머리글에 **점검**이 나온다(`주의 · 기한 지난 일 1 · …`, 문제가 없으면 줄에는 안 보이고 허브에는 "정상"). 노트에서 매번 계산하는 파생 값이며, 프로젝트 노트에 사람이 적은 `health:`(판단)와 **따로** 표시된다.

- **신호 4개**: 기한 지난 일(결정·대기 제외) · 확인일이 지난 결정 안건 · 기한이 지난 대기(상대 차례) · 담당자 없는 열린 일. 열린 일이 없는 프로젝트는 판단하지 않는다.
- **문턱은 한 곳**: [12장](#12-vault-안의-공유-설정-노트)의 `_workspace/설정.md`. 기본값은 기한 지난 일 1/3, 확인일 지난 결정 1/2, 늦은 대기 1/3, 담당자 없는 일 2/5 (주의/위험, "그 개수 이상이면").
- **만들지 않은 지표**: "며칠째 멈춘 일", "N일간 활동 없음" — 변경 시각을 줄·노트 단위로 믿을 수 없어서(동기화·가져오기로 바뀜) 정의가 불확실한 지표는 비워 둔다.
- 구현: `src/lib/health.ts`(순수 함수).

## 10. 타임라인

프로젝트 허브의 **타임라인** 탭은 프로젝트의 마감·업무·결정·일정을 **날짜순으로 한 줄에** 모아 보여 준다. 지난 항목은 흐리게, "오늘" 구분선 아래로 앞으로 올 것이 이어진다.

- 들어가는 것: 프로젝트 마감(`due:`), 마감일이 있는 업무와 결정 안건(완료된 것도 마감일 자리에 남아 결론이 보임), 프로젝트 노트의 일정. 취소된 업무는 뺀다. 마감일이 없는 열린 일은 개수만 안내한다("할 일" 탭에서 본다).
- 노트에 적힌 날짜만 쓴다(저장하는 데이터 없음). **"누가 언제 바꿨나" 같은 변경 이력은 만들지 않는다** — 마크다운에 줄 단위 이력이 남지 않고, 따로 기록하면 원본이 둘이 되기 때문이다.
- 구현: `src/lib/timeline.ts`(순수 함수).

## 11. 사용자 정의 타일

내 업무가 너무 길어지는 문제를 **사용자가 고르는 방식**으로 푼다. 헤더의 **화면 편집**(슬라이더 아이콘, 헤더에는 이 버튼만 있다 — 업무·일정 추가는 아래 입력 칸)을 누르면 편집 모드가 되고, 끝나면 "완료".

- **2열 배치**: 내 업무 화면(스크롤 영역) 너비가 980px 이상이면 타일이 2열 격자(`.wrk-tiles`, 행 순서: 1·2 / 3·4 …)로 놓인다. 창 너비가 아니라 이 영역의 너비(CSS container query)로 판단하므로 사이드바·패널이 열려 좁아지면 자동으로 1열. 한 열이 더 길면 옆 열 아래가 비는 점은 행 순서 격자의 특성이다(열 쌓기 방식은 순서가 읽는 순서와 달라져 택하지 않음).
- **정리 화면**: 편집 모드에서는 타일 내용 대신 **타일을 한 줄씩 늘어놓은 목록**(`TileArranger.tsx`)이 나온다. 한 줄 = 왼쪽 보이기 스위치 · 이름 · (줄 수 선택 · 사용자 타일은 "조건") · 오른쪽 손잡이 ⋮⋮. 숨긴 타일도 같은 목록에 흐리게 남는다.
- **순서**: 오른쪽 손잡이를 끈다. 터치에서는 줄 아무 데나 0.35초 꾹 눌렀다 끌어도 된다(그 전에 8px 넘게 움직이면 스크롤로 본다). 끄는 동안은 목록만 미리 바꿔 보이고 손을 뗄 때 한 번에 저장한다(숨긴 타일 순서도 함께 저장).
- **숨기기 / 보이기**: 줄의 스위치. 처음에는 이번 주·진행 중·담당자 없는 일이 숨겨져 있다.
- **줄 수**: 타일마다 처음 보일 줄 수(3 · 5 · 10 · 모두). 넘치면 "N개 더 보기". 오늘 일정·프로젝트는 기본이 "모두", 나머지는 5줄. 접기 상태도 기억한다.
- **내가 만드는 타일**: 편집 모드의 "+ 조건으로 새 타일 만들기"에서 이름을 붙이고 조건을 고른다 — 담당자(이름·"나"·"담당자 없음") · 프로젝트(전체·없음·이름) · 상태(할 일/진행 중/대기/결정할 일) · 마감(기한 지남/오늘/이번 주/마감일 없음) · 제목에 들어간 글. 조건을 바꾸는 동안 "맞는 열린 업무: N개"를 바로 보여 준다. 타일의 "조건"으로 고치고 지운다. 이름을 바꾸면 자리와 설정이 따라간다.
- **저장 위치가 둘로 나뉜다**: *배치*(순서·숨김·접기·줄 수)는 개인 취향이라 기기(`localStorage` `nosidian.worklayout`)에, *사용자 타일의 조건*은 팀이 같이 쓰도록 vault 의 `_workspace/보기.md` 에 사람이 읽는 줄로 둔다(직접 고쳐도 됨).
  ```md
  - 민수의 지난 일 :: owner=민수; due=overdue
  - 행사 준비의 결정 :: project=행사 준비; status=decision
  ```
  새로 생긴 타일은 처음에 맨 뒤에 붙고 보인다(다른 사람이 만든 타일도 내 화면에는 이렇게 나타난다).
- `owner=me` 는 설정의 "내 이름"을 쓰고, 내 이름이 비어 있으면 담당자 조건 없이 동작한다. 끝난·취소된 일은 나오지 않는다.
- 구현: `src/lib/tiles.ts`(배치 순수 함수) · `src/lib/views.ts`(조건 읽기/쓰기/적용) · `src/components/WorkHome.tsx`(타일 화면) · `ViewEditor.tsx`(타일 조건 편집기). *(이전의 "보기 선택 상자"는 직관적이지 않아 타일로 바꿨다. 이미 만든 보기는 자동으로 타일이 된다.)*

## 12. vault 안의 공유 설정 노트

팀이 같이 쓰는 값은 기기 설정(`localStorage`)이 아니라 vault 안의 노트에 둔다. 그래야 팀원 모두 같은 값을 쓰고 노트와 함께 동기화된다. 없으면 처음 쓸 때 설명과 함께 만든다.

## 13-1. 홈에 함께 보이는 날짜 체크리스트(과제)
업무(`due:`·프로젝트 소속)가 아니어도, **Daily 노트·빠른 입력으로 적은 시간 없는(종일) 날짜 체크리스트**는 홈의 `이번 주`(내일~7일 뒤)와 `기한이 지난 일`(어제까지 7일 안, 체크 안 한 것)에 업무와 함께 날짜순으로 보인다(`src/lib/dayItems.ts`). 시간이 있는 약속·반복·기간 일정·이미 업무로 잡힌 줄은 제외한다. 학생이 `다음주 월요일까지 수학 과제 제출` 처럼 적은 과제가 홈에 나오게 하려는 것(페르소나 F21). 습관성 줄: 같은 제목이 서로 다른 날짜에 2번 이상(간격이 모두 7의 배수인 매주 과제는 제외) 있으면 루틴으로 보고 `기한이 지난 일`에서만 뺀다(`이번 주`는 그대로). 한 날짜에만 있는 줄은 아직 루틴인지 알 수 없어 그날 지난 일에 보인다.

## 13-2. 노트 "업무 정리" (회의록 → 업무 쪼개기)
노트 ⋯ 메뉴의 `업무 정리`(열린 `- [ ]` 줄이 있을 때만 보임)는 그 노트의 열린 체크리스트 줄을 표처럼 모아 **제목·담당·마감·결정 여부**를 한 번에 정한다(`src/lib/noteTasks.ts`, `NoteTasksSheet.tsx`). 제목의 `(민수, 11/18까지)` `[지현]` `@민수` `11/18까지` `금요일까지` 는 읽어서 미리 채우고 "제목에서 읽었어요 · 원문"으로 확인하게 한다 — 괄호 안이 모두 이름·날짜일 때만(이름은 아는 이름이거나 같은 괄호에 날짜가 있을 때), `참고`·`긴급` 같은 말머리와 다른 글이 섞인 괄호는 그대로 둔다. 적용은 바뀐 줄만 꼬리표(`owner:` `due:` `kind:decision`)로 다시 쓰고(들여쓰기·일정 꼬리표 보존) 되돌리기 한 번으로 묶는다. 프로젝트 폴더 밖 노트라도 담당·마감이 붙으면 그 줄이 업무가 된다. **결정 사항**: 노트의 `## 결정`(`결정 사항`·`Decisions`) 머리말 아래 일반 글머리는 `결정 기록으로 남기기`를 켜면 완료된 결정 안건(`- [x] 안건 kind:decision => 결론`)이 된다(`행사 날짜는 12월 9일로 확정` → 안건 `행사 날짜` · 결론 `12월 9일로 확정`으로 나눠 채우며 고칠 수 있다, 기본은 꺼짐 — 회의록을 말없이 바꾸지 않는다). 프로젝트 허브 `문서` 탭의 `+ 문서 추가`로 그 프로젝트 폴더에 새 문서(회의록)를 만든다.

## 14. 아직 없는 것

- 템플릿 안의 반복 규칙·조건(예: 마감일 입력 시 일정 규칙을 머리말에 선언) — 지금은 `{{due±N}}` 자리표시자만
- 회의록 노트 안의 별도 안건 문법(`[decision]` …)
- 문단 이동·글자 단위 병합(줄 단위 병합까지만 — [15장](#15-팀으로-쓸-때-동기화충돌))
- 권한·승인·감사(소규모 신뢰 환경 전제. 조직용은 서버가 필요해 별도 결정)
- 프로젝트 팩(고객·계약·비용·리소스) — 특정 업무가 정해진 뒤에 얹는다

## 15. 팀으로 쓸 때 (동기화·충돌)

여러 사람이 같은 vault(GitHub 저장소·공유 Drive/OneDrive 폴더)를 쓰는 소규모 팀 기준이다. 서버가 없으므로 동기화는 각자의 기기가 같은 저장소를 읽고 쓰는 것이다.

**같은 노트를 동시에 고쳤을 때** (`src/lib/merge.ts`)
- 동기화 때 원격본이 바뀌어 있고 내 노트도 고친 상태면, **줄 단위 3자 병합**으로 합친다(기준 = 내가 고치기 시작했을 때의 내용). 고친 줄이 겹치지 않으면 자동으로 합쳐서 올리고 "자동 병합 N" 으로 알려 준다.
  - 서로 다른 줄의 수정·삭제·추가는 모두 반영, 이웃한 줄을 각자 고쳐도 합침(예: 두 사람이 인접한 업무를 각자 완료).
  - 같은 곳(예: 체크리스트 맨 끝)에 서로 다른 줄을 추가하면 **둘 다 남긴다**(내 것 먼저). 같은 수정은 한 번만.
  - 같은 줄을 서로 다르게 고쳤거나, 한쪽이 지운 줄을 다른 쪽이 고쳤으면 **충돌**로 남기고, 노트 위 안내에서 "다른 곳 N군데 보기"로 어디가 다른지 보고 내 버전 유지 / 원격 버전 사용 / 둘 다 보관 중에서 고른다.
- 올리는 사이 다른 사람이 먼저 올렸다(409/422)면 한 번은 알아서 다시 받아 합친 뒤 올린다.
- 병합 기준(`NoteFile.base`)은 노트를 **처음 고치는 순간**에만 저장하고 동기화되면 지운다(저장 공간 거의 안 늘림). 이 기능이 들어가기 전에 이미 고치던 노트는 기준이 없어 예전처럼 충돌로 처리된다.

**충돌을 줄이는 운영 요령**
- 회의록은 회의마다 노트 하나, 개인 메모는 사람마다 노트로 나눈다. 여러 사람이 줄을 더하는 공용 노트(예: `받은 업무.md`)는 위 병합으로 대부분 충돌 없이 합쳐진다.
- 같은 업무 줄을 동시에 바꾸는 일(담당자·상태 동시 변경)이 가장 흔한 실제 충돌이다. 업무는 담당자가 정해진 뒤 그 사람이 고치는 것을 원칙으로 한다.
- 팀 공유 값은 `_workspace/`(건강도 문턱·타일 조건)와 `Templates/`(프로젝트 템플릿)에 있다. 이 노트들도 위와 같이 합쳐진다.
- `owner:` 는 이름 문자열일 뿐 인증이 아니므로, 이름 표기(예: "민수")를 팀이 하나로 통일한다.
- 동기화는 앱을 열 때와 직접 누를 때 일어난다. 오래 켜 둔 뒤에는 한 번 눌러 합쳐 둔다.
