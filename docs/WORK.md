# 프로젝트·업무 (내 업무)

노트 앱 위에 얹은 소규모 팀용 프로젝트 관리. **저장하는 데이터는 새로 없다** — 프로젝트·업무·내 업무 대기열 모두 노트(마크다운)에서 매번 계산한다(`src/lib/work.ts`).
계획·배경은 [phase2/02-구현-계획.md](phase2/02-구현-계획.md).

## 1. 쓰는 법

### 프로젝트
노트 맨 위(프론트매터)에 `type: project` 를 넣으면 그 노트가 프로젝트다.

```yaml
---
type: project
status: 진행 중
owner: 민수
due: 2026-12-20
health: warning     # 사람이 판단한 상태(시스템이 계산하는 건강도와 별개)
title: 행사 준비     # 없으면 첫 번째 # 제목, 그것도 없으면 파일 이름
---
```

### 업무 한 줄
체크리스트(`- [ ]` / `- [x]`) 한 줄에 `key:value` 꼬리표를 붙인다. **체크박스는 표준 마크다운만 쓴다** — 다른 마크다운 도구에서도 그냥 체크박스 + 글자로 읽힌다.

```
- [ ] 장소 예약금 입금 due:2026-11-06 owner:민수 p:1
- [ ] 룸 가능 여부 문의 status:waiting side:other due:2026-11-08
- [ ] 현수막 시안 정하기 status:doing owner:지현
- [x] 날짜 확정 owner:민수 => 토요일 저녁으로 결정
```

| 꼬리표 | 값 | 뜻 |
|---|---|---|
| `due:` | `YYYY-MM-DD` | 마감일. **날짜가 따로 없는 업무는 이 날짜에 캘린더 일정으로도 나타난다** |
| `owner:` | 이름, 여러 명은 `owner:"홍길동, 김철수"` | 담당자 |
| `p:` | `1`~`3` | 우선순위(1이 가장 높음, 화면에 `!`) |
| `status:` | `doing`(진행 중) · `waiting`(대기) · `dropped`(취소됨) · 한글 `진행중` `대기` `취소됨`도 가능(예전 이름 `접음`도 읽음) | 상태. 없으면 "할 일". 완료는 체크박스(`[x]`) |
| `side:` | `me` · `other`(한글 `나` `상대`) | 공이 누구에게 있나. `other` 면 대기로 본다 |
| `proj:` | `proj:[[프로젝트 이름]]` | 소속 프로젝트를 줄 단위로 지정 |
| `impact:` | 한 줄 | 과업·비용에 미치는 영향 |
| `=> 결론` | 줄 끝까지 | 협의/결정을 닫을 때의 결론 |

기존 일정 꼬리표(`@날짜`, `end:`, `repeat:`, `until:`, 앞의 `14:00`)와 함께 쓸 수 있다. 일정 쪽은 업무 꼬리표를 제목에서 걷어 낸다.
모르는 `status:`/`side:` 값은 지우지 않고 글자 그대로 둔다.

### 내 이름 (팀)
설정 > 업무 > **내 이름**(쉼표로 여러 개/별명). `owner:` 가 내 이름을 포함하는 업무만 "내 것"으로 모은다. **담당자가 없는 일은 누구에게나 보인다**(배정해야 하므로). 이름이 비어 있으면 전체를 보여 준다.

## 2. 무엇이 "업무"인가

노트 안의 모든 체크리스트가 업무는 아니다(장보기 목록이 업무 대기열을 채우면 안 된다). 다음 중 하나여야 한다.
1. 업무 꼬리표가 하나라도 있다, 또는
2. 어떤 프로젝트에 속해 있다.

**프로젝트 소속**(우선순위 순): ① 줄의 `proj:` / 노트 프론트매터 `project: [[이름]]` → ② 프로젝트 노트가 있는 **폴더 아래**(가장 깊은 폴더가 이김) → ③ 프로젝트 노트 자신. 코드 블록 안의 체크리스트는 무시한다.

## 3. 내 업무 화면 (`WorkHome`)

앱의 **시작 화면**(PC·모바일 모두, 모바일 탭 "내 업무", PC 레일 첫 번째). 위에서부터:
- 오늘 일정(빠른 입력 포함). 업무 대기열에 이미 있는 항목은 중복해서 보이지 않는다.
- **기한이 지난 일** · **오늘 마감** · **이번 주**(7일 이내) · **대기 중인 일** · **진행 중** · **담당자 없는 일** — 각 줄에 *왜 여기 있는지*(`기한 3일 지남`, `D-3`, `대기 · 기한 1일 지남` …), 프로젝트, 담당자를 보여 주고, 체크하면 원본 노트의 `[x]` 가 바뀌며, 누르면 원본 노트가 열린다.
- 프로젝트 목록(상태·마감·열린 일 수).

규칙: 완료(`[x]`)·취소됨(`dropped`)은 어디에도 나오지 않는다. **상대 차례(`waiting`/`side:other`)는 내 기한 초과와 섞지 않고** "대기 중인 일"에만 나온다.

## 4. 업무 편집기 (GUI)

꼬리표를 몰라도 쓸 수 있도록 폼으로 입력한다. 결과는 위 문법의 한 줄로 노트에 저장된다.

- **열기**: 내 업무·프로젝트 허브의 업무 줄을 누르면 수정, 상단 **+**(업무 추가)로 새 업무. 줄 오른쪽의 노트 아이콘은 원본 노트 열기.
- **항목**: 제목 · 상태(할 일/진행 중/대기/취소됨) + 완료 · 결론(완료·취소됨일 때) · 마감일(오늘/내일/일주일 뒤 버튼) · 담당자(지금까지 쓰인 이름 제안, "나" 버튼) · 우선순위(높음/보통/낮음) · 프로젝트.
- **대기** = `status:waiting side:other` 두 꼬리표를 함께 쓴다(상대 차례).
- **수정은 그 줄만** 바꾼다: 들여쓰기·불릿, 일정 꼬리표(시간·`@날짜`·`end:`·`repeat:`·`until:`), 모르는 `status:`/`side:` 값을 보존(`rewriteTaskLine`). 그새 노트 위에 줄이 생겨 줄 번호가 밀려도 같은 제목으로 줄을 찾고(`findTaskLine`), 못 찾으면 아무것도 쓰지 않고 알린다.
- **새 업무의 위치**: 프로젝트를 고르면 그 폴더의 "할 일" 노트 끝에(없으면 새로 만듦, 프로젝트 노트가 폴더 밖이면 그 노트 끝에), 프로젝트가 없으면 **"받은 업무" 노트**에 모은다(나중에 옮길 수 있음). 폴더로 이미 소속되므로 `proj:` 꼬리표는 쓰지 않는다. 기존 업무의 프로젝트를 바꿀 때만 `proj:[[이름]]` 을 쓴다.
- 삭제는 확인 창을 거친다. 노트 이름(할 일·받은 업무)은 UI 언어를 따른다.

## 5. 프로젝트 허브

내 업무의 프로젝트 목록을 누르면 열린다(레일/탭은 "내 업무"가 활성). 읽기 화면이고 고치는 건 업무 편집기.
- 머리글: 프로젝트 이름(title > 첫 # 제목 > 파일 이름), 상태·담당·마감·사람이 입력한 판단(`health`)·열린 일 수, **+** 업무 추가, 노트로 열기.
- **할 일** 탭: 진행 중 · 할 일 · 대기로 나누고(각 마감일순), 완료·취소됨은 접어 둔다(결론은 줄에 `→ 결론`으로 표시).
- **문서** 탭: 프로젝트 폴더 아래의 노트(프로젝트 노트가 폴더 밖이면 안내).
- **일정** 탭: 이 프로젝트 노트들의 일정·마감(지난 14일 ~ 앞으로 120일), 업무 줄은 편집기로 연결.

- **보드** 탭: 할 일 · 진행 중 · 대기 · 완료 네 칸의 칸반. 카드를 끌어 놓거나 카드 오른쪽 ‹ › 로 옮기면 그 줄의 `status`(대기는 `side:other` 포함)·완료 체크만 바뀐다(`moveTask`). 취소됨은 보드에 나오지 않는다. 모바일은 칸을 옆으로 넘겨 본다.

## 5-1. 새 프로젝트 마법사 · 템플릿

내 업무의 "+ 새 프로젝트"(또는 명령 팔레트 "새 프로젝트")에서 템플릿을 고르고 이름·마감일·담당자를 넣으면 `프로젝트/<이름>/` 폴더에 문서가 만들어지고 허브가 열린다.
- **템플릿 3종**: 일반(개요+할 일) · 행사(마감일에서 거꾸로 잡힌 준비 일정 7개 + 회의록) · 콘텐츠(기획→제작→검수→배포 6단계). 결과는 평범한 노트라서 만든 뒤 자유롭게 고친다.
- **자리표시자**: `{{name}}` `{{owner}}` `{{due}}` `{{today}}` `{{due-14}}`(마감일 14일 전). 마감일·담당자를 비우면 그 꼬리표는 줄에서 빠진다. 같은 이름의 폴더가 있으면 ` (2)` 를 붙인다.
- 구현: `src/lib/projectTemplates.ts`(순수 함수, 테스트 포함) + `src/components/NewProject.tsx`.
- 아직 없음: 사용자가 vault 의 `Templates/` 폴더에 직접 만든 템플릿 읽기.

## 5-2. 받은 업무 정리

프로젝트 없이 적어 둔 업무(주로 "받은 업무" 노트)는 내 업무에 **정리할 업무** 섹션으로 모인다(프로젝트가 하나라도 있을 때). 줄의 "프로젝트로 옮기기…"에서 프로젝트를 고르면 그 프로젝트의 "할 일" 노트로 **줄이 옮겨 간다**(마감·담당·우선순위·상태는 그대로, 원래 노트에서는 지워짐 — `moveToProject`). 편집기의 프로젝트 선택은 `proj:` 꼬리표만 바꾸는 것과 구분된다.

## 7. 아직 없는 것 (P2-1 남은 작업)

vault 폴더의 사용자 템플릿 읽기. 이후 P2-2: 결정·미결(닫을 때 결론 강제), 받은 편지함 정리(프로젝트로 옮기기), 타임라인, 건강도.
